# SQLite 存储改造：增量持久化阶段

## 已落地

工作区使用 `workspace.sqlite`；活动与专注分别使用 `modules/task-activity.sqlite`、`modules/focus.sqlite`。使用系统 SQLite3，不引入第三方依赖。其他小型模块与偏好继续沿用原存储。

工作区元数据、任务、任务正文、笔记、笔记正文分别存表。任务表有清单/状态、父任务和日期索引，笔记表有文件夹索引。正文保留现有 NativeDocument 的 JSON 编码，作为单条数据库记录保存；笔记导入的原始富文本内容也保留。

任务保存订阅 TaskChangeSet，不再依赖 UI revision 构造整个工作区快照。文本更新仅发送一个任务变化；结构变化才携带任务 ID 顺序。笔记在 NoteStore 的修改边界发布具体新增、修改、删除和排序变化。清单/文件夹元数据独立保存，不带任务和笔记数组。

后台串行队列合并 400 ms 内的变化，以一个事务写入该批任务、笔记与工作区元数据。相同实体连续编辑保留最后状态，同时合并正文是否变化的标记。任务/笔记只改标题或归属，不编码、重写正文。失败的批次保留，flush 重试；退出保存沿用队列屏障顺序。

历史记录逐条保存，专注偏好和正在进行的会话与历史记录分开。追加记录不重新编码已有历史；活动标题合并与撤回仍支持更新/删除最后事件。第一阶段保留历史数组在内存，后台逐条比较后只写变化记录；任务动态现已进一步改为精确增量写入，见下文。

各数据库使用 WAL、FULL 同步配置和 busy timeout。当前连接按操作打开/关闭，利用 SQLite 默认 checkpoint 行为；尚未做长期连接与独立 checkpoint 调度的性能优化。

## 迁移、备份和导出

首次打开旧工作区时，读取旧 JSON，检查版本，事务导入并读回核对任务、笔记和工作区元数据。只有事务提交后的 metadata 记录存在，数据库才成为权威数据。失败不提交迁移标记；原 JSON 保留且不继续双写。活动、专注旧 JSON 同样保留，迁移后以数据库初始化标记为准；模块读取失败会停用该模块写入并上报错误。

每日与手动工作区备份改为独立 SQLite 文件，通过 backup API 包含已提交的 WAL 内容。保留原来的 7 份保留策略；恢复兼容旧 JSON、新 SQLite 和旧整目录工作区备份。整目录备份工具对数据库使用 backup API，不直接复制活动 WAL 文件。

设置中的备份、导出先 flush，读取最后输入后的数据。旧合并导出格式保留 JSON，但数据优先取数据库，活动和专注也重新组装为原导出格式，避免导出迁移后停止更新的旧文件。

导入/恢复前 drain 当前保存队列；成功后暂停旧工作区的保存并提示重启，当前页面禁用，防止退出时旧内存覆盖新数据。失败恢复正常保存。数据库记录的替换发生在事务内。活动和专注数据库仍是独立模块，不与工作区共用跨库事务。

## 第二阶段的边界

任务动态与专注记录已接入分页；任务和笔记正文已接入延迟读取及摘要预览。启动仍全量读取任务、笔记的元数据，用于现有内存索引和页面投影；没有把所有实体查询改成数据库分页。数据库首次迁移/升级会读取旧正文回填摘要与纯文本列，迁移后的正常初始化才避免全量正文加载。

未加载正文是延迟引用，不能编码成空正文。实际编辑、复制、转换和导出按需读取完整文档。首次打开单篇正文仍同步读取，搜索新关键词仍扫描纯文本列，已消除富文本解析但没有消除所有查询成本。

## 第二阶段进展：任务动态分页

TaskActivityStore 初始化仅读取最后一条事件，用于连续修改标题的合并。新增/修改/删除按事件 ID 直接提交，不再提交或比较完整历史数组。清单动态根据当前任务所属清单取得任务 ID 集合，在数据库中筛选，不再先读取所有事件再在内存中过滤。

任务动态与清单动态共用 TaskActivityPageModel：每次取 51 条，显示 50 条，额外一条判断下一页；提供加载状态、读取失败重试和加载更多。查询及待保存增量提交在 utility 队列顺序执行，查询返回时已包含刚产生的事件。打开动态面板时，待保存增量会提前提交，不再等待 400ms 防抖结束；未打开面板时仍按原防抖保存。

事件变化或清单任务集合变化会重置分页，避免新事件导致 offset 偏移而重复或漏项。被取消、过期的异步请求不能覆盖当前页面。任务浮层固定为 396pt 高，避免异步加载结束后窗口尺寸变化破坏定位。历史索引版本升级为 2，增加 position 索引，日期及任务日期索引包含 position，支持相同时间的稳定排序，并让追加记录计算最大 position 使用索引。

完整 events 与同步 events(for:) 仍保留兼容访问；这些访问会显式读取历史，但两个生产动态面板已不再调用。设置导出仍按需求读取完整历史。

验证：

- 10,000 条历史，迁移后的下次启动解码 1 条；打开任务面板后累计解码 52 条。连续加载两页无重复，相同时间的事件顺序正确。
- 新增事件立即可见，重新打开数据库后仍保留全部 10,001 条历史。
- 标题变更在重启后仍可合并，恢复原标题正确删除合并事件。
- 103 条事件正确分为 50/50/3，结束后不再查询；空清单不读取其他任务动态。
- 扩展回归 124 项通过；曾发现加载状态改变导致动态浮层越界，固定高度后同一回归通过。

最终整理后的专项回归 54 项通过，Release arm64/x86_64 构建通过。

## 第二阶段进展：专注历史分页和统计

FocusStore 启动读取偏好、计时器、正在进行的会话及数据库聚合结果，不再加载完整 PomodoroRecord 数组。进入专注页面后异步读取 51 条、显示 50 条，支持加载更多及读取失败重试。补记或删除会重置分页，查询以时间和 position 稳定排序。完整 records 仍保留显式兼容访问，生产记录列表使用 visibleRecords。

累计分钟与番茄数独立于分页。在历史表中增加 metric_value（分钟）与 metric_count（完成番茄数）标量列和统计索引，数据库版本升为 3。现有 SQLite 数据库首次升级时回填标量，保留原记录 payload；后续统计无需解码历史 JSON。累计总数在初始化时 SQL 聚合，之后按单条新增/删除更新内存缓存。每日与按任务统计使用日期范围 SQL 聚合，日期边界来自应用 Calendar，保持当前日期口径。

今日统计按日期缓存，计时刷新不再每秒筛选全部记录或查询数据库；记录新增、删除直接调整今日缓存，跨天查询一次重新建立缓存。删除未加载记录按 ID 读取一条记录，用其分钟、完成状态和日期更新完整统计。

偏好、计时器、会话快照和会话笔记采用独立 metadata 增量保存；记录新增/删除与最新 metadata 在同一数据库事务提交。分页内容不能成为整个数据库的替换快照，未加载记录不会因会话保存被删除。

验证：

- 10,000 条历史，迁移后的下次启动记录解码数为 0；进入页面读取 51 条，两页显示 100 条且无重复。
- 只加载两页时，累计仍为 20,000 分钟、5,000 个番茄；删除未加载记录、补记与修改目标后重启，完整统计及全部历史正确保留。
- 活跃计时连续刷新 100 次，没有新增统计查询；跨天刷新统计，累计保持不变。
- SQLite 版本 2 升级为 3，记录 payload 和偏好保持不变，累计统计正确。
- 专注状态、布局、时间线、任务选择、动态、SQLite、设置和迁移相关回归 111 项通过，0 失败。

最终活跃计时验证的专注专项 13 项通过，Release arm64/x86_64 构建通过。

日志：`/private/tmp/wf-focus-pagination-regression.log`、`/private/tmp/wf-focus-pagination-final-tests.log`；发布构建日志：`/private/tmp/wf-focus-pagination-release.log`。

## 第二阶段进展：任务与笔记正文按需读取

AppEnvironment 改用 loadDeferred，只读取任务/笔记元数据和 DocumentSummary。文档携带共享的不可变读取引用，首次读取 blocks/plainText 才查询并解码完整 NativeDocument，结果缓存。编辑赋予新的文档值，不改变旧引用中的块和格式；元数据修改沿用同一引用，比较任务变化时不触发正文读取。

工作区数据库版本升为 2，任务/笔记表增加短摘要，正文表增加纯文本列。摘要保存首尾各 160 字符、长度、空文档状态、任务首个非空行以及笔记原始富文本存在标记。任务行与笔记行使用摘要预览，笔记受保护状态不必加载原始富文本 JSON。原始富文本源本身同样按需读取，完整导出保留原数据。

任务查询、已保存筛选、笔记搜索和命令面板保持原有大小写/本地化匹配语义，使用完整纯文本列查找正文中间的内容。匹配结果缓存最多 64 个查询，正文变化后失效；普通任务标题变化不清除正文匹配缓存。内存中已编辑但未保存的文档直接匹配新值。该实现使用纯文本列扫描和匹配结果缓存，并非 FTS 全文索引。

正文编辑器先 materialized；读取失败展示错误而不创建可编辑文本视图，编码失败也不会产生空文档。仓库记住正文读取错误并拒绝后续增量提交，应用显示保存停用信息。任务转笔记先核验正文读取成功。存储层继续只在正文变化时写正文表，不会因为延迟引用或只改标题而重写正文。

可撤销移除任务前会加载待移除任务的正文，避免数据库级联删除后撤销引用失效。正文编辑的旧值同样保留块身份与富文本格式。永久清除仍遵循原有清空业务撤销记录的规则，并没有新增永久删除后的撤销功能。

- 标题、笔记标题和文件夹修改后保存，正文与原始富文本读取次数均为 0，重读数据库正文和原文完整保留。
- 首次富文本读取只解码 1 次，重复访问命中缓存；编辑后旧值的块身份、标题样式和标记不变。

- 任务转笔记、受保护笔记纯文本副本、转换撤销及导出保持完整正文；受保护状态和创建纯文本副本不读取原始富文本源。

# macOS 改造复核

日期：2026-09-12  
分支：`feature/flutter-personal-desktop`  
范围：本轮 9 次提交涉及的 28 个文件，对照上一轮改造方案，执行源码审查、自动验证及部分实机检查。

## 结论

已有明显进展，但不能认定“全部修改完成”。基础功能测试与构建通过，仍有影响正常使用的断点。建议先修下列 P1，再继续功能扩展。以下均给出具体触发条件，不基于罕见故障场景推演。

本次只新增检查报告，没有修改产品代码；临时回归测试已从产品测试目录移除。实机没有导入、删除或修改用户任务/笔记，也没有改变通知授权。

## 已验证的改进

- 现有 `flutter test`：42 项全部通过。
- `dart analyze --format machine`：0 error、0 warning、39 info；静态检查达到可继续开发的状态。
- `flutter build macos --release`：成功生成正式构建。
- 实机能够启动；Cmd-, 能打开设置；统一侧栏与任务/笔记入口可见。
- 代码和现有行为测试覆盖了上下文创建、无日期分组、任务/笔记软删除、真实日历查询、命令面板、基础重复/子任务、多选、主题持久化以及任务—笔记关系等改进。

这些结果说明基础改造已经落地，但现有测试遗漏了若干跨功能和原生平台流程，不能代替以下验收。

## 需要先修复的缺陷

### R1 · P1：正式包无法打开导入/附件文件面板

**证据：实机＋系统日志＋构建产物权限。**

- 复现：启动正式包 → Cmd-, → 数据 → 选择文件。文件面板未出现。
- 23:32 的应用日志明确指出：`Unable to display open panel: your app is missing the User Selected File Read app sandbox entitlement.`
- 正式包的签名权限中没有 `com.apple.security.files.user-selected.read-only` 或对应读写项；`Release.entitlements` 和 `DebugProfile.entitlements` 也未声明。
- 位置：`desktop/macos/Runner/Release.entitlements:5`；`MainFlutterWindow.swift` 中的 `pickMigrationFile`、`pickAttachmentFile`。
- 影响：个人数据迁移被阻断；附件使用相同文件面板机制，也缺少必要权限。增加 Dart 侧功能或测试替身无法修复这个原生问题。
- 修复：按实际操作补齐用户所选文件的权限，确保 Debug/Release 一致；重新构建并核对产物。实机分别完成“打开迁移文件并显示预览”和“添加沙盒外的一个文件”。

### R2 · P1：快速录入的 Return 提交路径必定提前返回

**证据：Swift 对象结构静态确认；Dart 端另有行为探针复现。**

- `makePanel` 创建的是普通内容视图，输入框通过 `panel.contentView?.addSubview(field)` 加入其中。
- `submit` 却执行 `panel?.contentView as? NSTextField`，这个转换得到 nil，guard 直接返回。即使面板打开且成功输入，Return 也不会走到发送内容、清空或关闭面板。
- `showPanel` 的设置输入焦点也使用了同样的错误转换。
- 位置：`desktop/macos/Runner/MainFlutterWindow.swift:518`、`:538`、`:489`。
- 修复：保存输入框引用，用同一个输入框设置首个响应者、读取和清空内容；提交以 Dart 明确接受结果为准，失败保留输入。
- **同时修正捕获语义**：Dart 快速录入只显式传 `listName: '收集箱'`，日期仍由 `addTask` 的 `_creationDueDate()` 推断。应用停在“今天”时，后台速记会自动被安排今天。通过平台消息注入已复现。需要独立的“无日期收集”命令，不能依赖主窗口当前页面。
- 验收：从其他应用唤起，输入标题，Return 后关闭；新任务只在无日期收集箱；主窗口停在今天、清单或笔记均得到相同结果。

### R3 · P1：提醒界面仍无法设置具体时间，选择今天会取消提醒登记

**证据：提醒编辑 UI 与调度分支直接核对。**

- `task_inspector.dart:537` 只调用 `showDatePicker`，随后把返回的日期直接传入 `updateTaskReminder`；没有选择小时和分钟的步骤。
- 选择今天得到当天零点。`_syncReminderFor` 要求提醒严格晚于当前时间，因此在一天中的正常使用时段会走 cancel 分支。
- 位置：`desktop/lib/widgets/task_inspector.dart:537`；`desktop/lib/state/workspace_controller.dart:1399`。
- 影响：用户无法创建“今天下午三点提醒我”；界面可能显示今天的提醒日期，系统实际上没有登记。
- 修复：提醒必须包含可编辑时刻；已过去的时刻要明确提示或要求修改。任务日期本身也应有可选时间，并保留全天语义。
- 验收：选择今天未来几分钟的提醒，界面显示准确时刻，并在实际系统中登记和投递。

### R4 · P1：完成重复任务后，下一次显示提醒但没有系统通知

**证据：新增控制器回归探针复现。**

- 复现：创建未来两天到期的每日重复任务，设定提前一小时提醒 → 完成当前任务。
- `_spawnNextRecurrence` 已为新任务计算 `shiftedReminder`，但 `toggleTask` 只调用 `_syncReminderFor(updated)` 取消原任务提醒，没有登记 spawn。
- 探针结果：新任务 `reminderAt` 非空，调度器中却不存在新任务 ID。批量完成也只有原任务调度调用。
- 位置：`desktop/lib/state/workspace_controller.dart:777`、`:785`；`bulkCompleteSelected` 同样需要处理。
- 影响：任务详情承诺了下一次提醒，但应用保持运行时不会提醒；重启全量同步后行为又可能改变。
- 修复：完成时同时同步原任务和新实例；撤销时取消被移除实例的通知并恢复原任务。不要仅依赖启动时全量同步补救。
- 验收：单个/批量完成后，系统登记与所有有效实例一致；撤销后没有遗留通知。

### R5 · P1：连续编辑时，“已保存”仍可能早于最新编辑落盘

**证据：控制两次保存完成时机的回归探针复现。**

- 复现：连续编辑标题两次，让第一次写入完成、第二次仍处于待写状态。
- 每个 `_schedulePersist` 调用完成后都无条件把共享 `_saveStatus` 改成 saved。第一次保存结束时，第二次还未完成，界面已经显示已保存。
- 探针结果：预期 `SaveStatus.saving`，实际 `SaveStatus.saved`。
- 位置：`desktop/lib/state/workspace_controller.dart:1931`–`:1935`。
- 影响：快速打字这种普通场景下，用户仍无法根据状态判断最新内容是否落盘。当前退出逻辑也没有等待保存队列完成的接口。
- 修复：用编辑版本/待保存数量跟踪最新内容，仅最新版本完成后显示 saved；退出时完成待保存写入。
- 验收：第一笔完成而第二笔未完成时保持保存中；最后一笔完成才显示已保存；按此状态退出再打开，内容与最后一次编辑一致。

### R6 · P1：编辑导入笔记会静默删除原有富文本结构与链接

**证据：带真实结构的最小导入样本回归探针复现。**

- 复现：导入一条有文字链接的笔记 → 在纯文本正文末尾加一行。
- `updateNoteBody` 将整个 contentJson 替换为从纯文本生成的 paragraph/text 节点。链接的 href、marks，以及标题、图片和其他非纯文本结构均没有保留路径。
- 探针结果：原链接地址从笔记的序列化记录中完全消失，并非只是当前界面不显示。
- 位置：`desktop/lib/state/workspace_controller.dart:1797`；`desktop/lib/models/task.dart` 的 `noteContentJsonFromPlainText`。
- 影响：上轮的“两份正文不一致”问题被转换成内容损失。富文本编辑器暂缓是可接受的产品取舍，但不应因此让普通编辑隐式转换并覆盖原文。
- 修复：接入兼容结构的编辑器，或保留导入原件并提供明确的“转换为纯文本副本”操作。现有普通纯文本笔记不受此限制。
- 验收：导入含链接/列表的笔记并追加正文后，原链接及结构仍可恢复、导出和继续使用。

### R7 · P1：导入 UTC 时刻的任务仍按 UTC 日期归入日历

**证据：在 Asia/Shanghai 环境运行回归探针复现。**

- 复现：导入 `2026-09-12T16:30:00Z`，对应本地 9 月 13 日 00:30。
- `tasksForDay` 直接比较解析结果的 year/month/day，没有先转换本地时区；查询 9 月 13 日得到空结果。
- 日期分组、文案和拖动保留时刻等路径也直接使用解析后的字段，需要统一处理。
- 位置：`desktop/lib/state/workspace_controller.dart:585`–`:589`；`desktop/lib/models/task.dart` 的日期辅助函数。
- 修复：明确区分全天日期与带时区的时刻；后者在显示、分组和编辑前统一转本地时间，不要把 UTC 的时分重建成同数值的本地时刻。
- 验收：上述样本在本地 9 月 13 日显示 00:30，拖动到另一日仍保留本地 00:30；无日期任务继续保持无日期。

## 体验缺陷

### R8 · P2：窄窗口返回详情后，列表滚动位置归零

**证据：修正定位后的 Widget 回归探针复现。**

- 使用 60 条任务，滚动到 1580 pt，打开详情再点击返回；实际滚动位置为 0。
- `TodayScreen` 虽创建了 Offstage，但进入 `narrowDetail` 时直接 return 一个 TaskInspector，列表根本没有留在组件树中。
- 位置：`desktop/lib/screens/today_screen.dart:69`–`:74`。
- 修复：保留两侧的组件状态，或按视图管理 ScrollController/PageStorage；切换任务视图时也明确恢复策略。
- 现有窄窗测试只检查返回后能找到任务文字，没有验证滚动位置，因此此前通过不能说明“返回保留滚动”已经实现。

### R9 · P2：首页宽度计算遗漏内边距，双列永远放不下

**证据：实机截图与布局计算吻合。**

- 实机首页卡片堆在左侧，右侧大面积空白。
- `panelWidth = (constraints.maxWidth - 14) / 2` 使用外层宽度，但 Wrap 实际处于左右各 28 pt 的 padding 内。
- 两张卡片加 14 pt 间距刚好等于外层宽度，始终比实际可用宽度多 56 pt，于是被换成单列，同时保留半宽卡片。
- 位置：`desktop/lib/screens/home_screen.dart:46`–`:50`。
- 修复：在 padding 之后做 LayoutBuilder，或先减去内边距再计算列宽；窄窗口单列同样使用实际可用宽度。
- 验收：1280 级窗口正常显示两列，窄窗口使用完整内容宽度的一列，不出现半屏留白。

## 建议的修复顺序

1. **先恢复正常入口**：R1 文件权限、R2 快速录入。
2. **再修内容与状态可信度**：R5 保存状态、R6 导入笔记内容保留、R7 本地日期。
3. **完成提醒流程**：R3 时间选择、R4 重复实例登记；实机验证后再标为完成。
4. **收尾窗口体验**：R8 列表返回、R9 首页列宽，然后核对其余方案缺项。

无需扩大测试数量来证明完成。把上述具体失败场景纳入回归，并在 release 包实际执行导入、快速录入、当天提醒和重复提醒，比继续补只验证字段赋值的测试更有价值。

## 验证记录说明

临时探针验证了 6 个失败场景：重复提醒登记、连续保存状态、UTC 归日、富文本链接保留、窄窗滚动恢复、全局收集日期。窄窗探针第一次读取到了文本输入控件的滚动状态，未形成结论；修正为读取任务列表的 Scrollable 后，复现 1580 → 0。

通知到点投递、通知点击后主窗口前置、外部应用到录入面板的完整焦点往返、VoiceOver、减少动态效果和大数据性能尚未实测通过。源码发现和探针复现没有被写成这些实机项目已经通过。

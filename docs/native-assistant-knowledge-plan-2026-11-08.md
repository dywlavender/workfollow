# WorkFollow 个人助手与本地知识检索实施方案

2026-11-08 · macOS 原生版

## 首版目标

打开 AI 对话页就能看到今天值得处理的事。会后能从原话确认待办，临期时看到仍未完成的承诺。想核对一项决定时，可以在 `⌘K` 搜索或直接问助手，点回命中的笔记段落或任务。

首版分三段交付。先做可操作的今日简报和定时结果送达，再接通笔记与待办的共享全文索引，最后把会后候选接到今日助手。今日助手与全文索引可以独立开发。会后流程使用指定会议的定稿资料，待办跟进复用今日助手的规则。

App 负责读取当前事实、判断触发条件、保存结果和执行业务动作。Pi 负责理解自然语言、提取承诺和组织回答，复用现有会话、内置 Skill 和 `workfollowctl`。后台默认交付摘要或草稿。用户明确委托的自动写入走原生业务接口，以保存回执为准。方案基于当前原生工作区源码及仓库已有的隔离实测记录。[个人助手现状](native-personal-assistant-2026-11-03.md) · [定时执行现状](native-ai-scheduled-tasks-2026-11-03.md) · [本地问答现状](native-ai-knowledge-workflows.md)

## 1. 今日助手与结果送达

在现有 AI 对话页顶部呈现少量待处理事项，默认显示最重要的三条，更多结果按需展开。一条只需要事项标题、为什么现在要处理，以及一个主要动作。点击标题打开原任务或结果。改期打开现有日程面板，设提醒和完成走原生任务操作，成功后显示实际回执。

- **任务事实**由 `AssistantBriefingFacts` 的原生投影提供。优先展示已逾期或临近截止且未完成的事项。安排逾期和截止临近分别使用已有日期语义，同一任务合成一条。任务保存、完成、改期或跨日时重新计算，已处理事项从列表收起。Pi 的简报文字可按日缓存，模型不可用时也能看到并处理任务。[简报事实投影](../macos-native/WorkFollow/Application/AssistantBriefingStore.swift)
- **定时结果**由计划上的「完成后告诉我」选项控制送达。运行结束并保存对话后，在记录本轮状态时写入一条带 `runID` 和 `conversationID` 的结果索引。完成时可查看结果，失败或中断时显示状态和已有结果。按 `runID` 去重，用户处理后收起。交付记录存引用，正文从对话读取。[定时任务执行器](../macos-native/WorkFollow/Application/AIScheduledJobRunner.swift) · [结果跳转与简报入口](../macos-native/WorkFollow/App/AppEnvironment+Assistant.swift)
- **个人偏好**复用助手记忆。表达习惯交给模型参考，通知开关、默认提醒等直接影响执行的偏好用原生设置字段。用户当轮明确指定的安排优先。首版结果在 App 内可见，系统通知作为可开启的后续交付方式，只对明确订阅的结果发出并跳到对应事项。[助手记忆](native-personal-assistant-2026-11-03.md)

验收时在完整窗口打开助手，点一条临期任务并改期，核对任务实际保存和列表随之更新。让定时计划在用户看另一页时运行，回到助手后直接打开结果。核对正常、失败和中断状态，恢复后每轮只出现一条交付记录。

## 2. 笔记与待办的本地检索

目前 `⌘K` 和「问 AI」分别使用字面匹配与片段评分。新正文词可能触发纯文本扫描，普通搜索在命中长文中段时可能显示首行。新索引统一提供候选、排序和命中原文，三个入口按各自用途展示结果。[普通搜索与预览](../macos-native/WorkFollow/Features/Shell/CommandPaletteProjection.swift) · [现有问答检索](../macos-native/WorkFollow/Application/KnowledgeRetrieval.swift)

### 建索引

- 在 `workspace.sqlite` 中增加可重建的 SQLite FTS5 索引。索引从业务记录派生，笔记按当前笔记类型投影，任务按实际任务类型投影。短记录按条索引，长正文沿标题和段落切分。片段保留记录 ID、类型、段落锚点、标题、小节和原文。展示和引用读取原文，分词文本供匹配使用。[笔记投影](../macos-native/WorkFollow/Features/Notes/NotesWorkspaceModel.swift) · [正文结构](../macos-native/WorkFollow/Domain/Document/NativeDocument.swift)
- 首次构建和导入恢复后按批填充。索引尚未就绪或需要重建时，使用现有搜索。复用 `TaskChangeSet` 与 SQLite 的后台写入批次更新索引。正文变化重建该条记录的片段，状态或归属变化只更新相应字段，删除和恢复随业务变更处理。已提交记录走索引，保存队列中的编辑按记录 ID 合并最新值。首建批次读取当时的记录，避免用旧快照覆盖新编辑。[增量写入](../macos-native/WorkFollow/Infrastructure/Persistence/SQLiteWorkspaceRepository.swift)

### 匹配、过滤和排序

- 正文和查询使用同一套中文分词，优先复用 `NLTokenizer`。对短词、项目名和带标点的编号保留精确子串匹配。已有本机小样中，「周会」在连续中文里用默认或三元分词都返回 0 条，预分词后返回 1 条。发布前在最低支持的 macOS 版本验证 FTS5 和短词命中。[SQLite FTS5 分词说明](https://sqlite.org/fts5.html#tokenizers)
- 标题和编号的精确命中优先，其余候选按标题、小节、清单或文件夹、标签与正文的匹配度排序。结果按记录 ID 归并，展示最相关的原文片段。点击后优先定位段落锚点，锚点变更时用可核对的原文匹配当前位置。
- 查询显式区分资料类型、清单或文件夹、标签、完成状态和日期口径。任务的安排、截止和完成时间分别使用对应字段。「本周截止的未完成任务」从实际任务记录取完整列表和计数，再按需找笔记佐证。[任务字段](../macos-native/WorkFollow/Domain/Task/Task.swift) · [现有 CLI 任务筛选](../macos-native/WorkFollow/Application/NativeAutomationMaterials.swift)

### 接入入口

`⌘K` 将资料命中与现有快捷命令共同呈现。「问 AI」及 `knowledge.search` 调用同一检索服务。「海鸥项目本周截止的未完成任务有哪些？验收标准是什么？」分别查待办字段和关联笔记正文，有现成来源关系时优先查对应笔记。会议候选由现有会议检索提供，并与笔记、任务结果合并。

检索在本机完成。「问 AI」只把本次选中的原文片段交给已配置的模型，复用现有片段预算、来源编号和连续摘录校验。Agent 要操作记录时按 ID 读取最新业务数据，引用使用检索返回的实际链接。[问答预算与引用校验](native-ai-knowledge-workflows.md)

验收时用同一组查询对照当前版本。记录正确资料是否出现在前五条、从输入到首批结果的 P95 耗时、打开后是否定位到命中原文。短词、项目编号、长笔记中段和显式任务筛选作为必过项。编辑保存、删除后恢复、旧工作区重建各走一次，核对索引与实际资料一致。

## 3. 会后跟进

1. 在设置的「助手记忆」里开启「会后提取待办」，在会议页点击「结束会议」。App 等尾段转写处理完并保存后，再从定稿发言提取一次。录音中途可用「暂停录音」继续保留录音进度。只有手写纪要的会议可以用「提取待办」入口发起。[会议停止与转写生命周期](../macos-native/WorkFollow/Features/Meetings/MeetingStore.swift)
2. 复用 `AITaskRequest`、`AITaskDraft` 和候选确认面板。候选显示行动、原文依据及明确的截止时间。带原发言的候选能点回发言，时间不明确时留给用户填写。候选按会议 ID 与资料修订号持久化。同一版资料的重复触发更新原候选批次，用户在今日助手里确认需要创建的项。[现有会议提取与采用](../macos-native/WorkFollow/App/AppEnvironment+AITasks.swift) · [待办候选模型](../macos-native/WorkFollow/Application/AITaskDraft.swift)
3. 确认时核对来源和已关联任务，沿用现有原生创建、来源关联与去重，保存成功后收起对应候选。之后按任务的实际截止日期和完成状态跟进。改期后根据新日期计算，完成后结束跟进。[待办采用与去重](../macos-native/WorkFollow/Features/Tasks/TaskWorkspaceModel.swift)

验收使用一场包含「周三 16:00 前发验收清单」的会议。会后出现候选，点击能找到原话，确认后得到关联会议的待办。重复触发同一版会议资料时只出现一条对应待办。跨日仍未完成时显示临期事项，完成后自动收起。

## 4. 按实际需求推进的能力

| 能力 | 启动条件 | 实现与验收 |
| --- | --- | --- |
| 语义检索 | 全文索引上线后，代表查询仍反复漏掉同义说法 | 对同一批段落生成本地向量，随段落更新，从资料范围内独立召回，再和关键词排序合并。对照「等对方回复」和「待供应商回函」一类查询，检查前五条召回是否提升，并复测短词和编号。 |
| 日程建议 | 日常查询出现「留一段时间做某事」或避开会议的需求 | 按所问日期查询已授权的系统日历，和任务安排、工作时段、所需时长一起计算候选。显示日历覆盖范围，用户确认后写入 WorkFollow 的安排字段。验收覆盖已知会议冲突、时长和实际保存时间。 |
| 退出后按时执行 | 用户需要在 WorkFollow 进程退出后仍准点执行 | 单独设计常驻执行入口、运行状态和恢复规则。明确系统休眠与登录后的处理方式，复用任务计划的运行标识与业务保存回执。当前版本在 App 运行时到点执行，恢复时只补最近错过的一轮。 |

日历可复用原生系统日历读取服务，助手按查询时间范围取事件。当前简报仅包含 WorkFollow 任务，建议可用时段前须获得足够的日历数据。[系统日历服务](../macos-native/WorkFollow/Infrastructure/Calendar/SystemCalendarService.swift) · [当前简报的资料范围](native-personal-assistant-2026-11-03.md) · [当前定时规则](native-ai-scheduled-tasks-2026-11-03.md)

## 验证方式

实施前用固定时钟和隔离工作区记录基线，为样例标注预期来源、任务字段和操作结果。复用工作区搜索、知识检索、SQLite 持久化、助手交互、定时任务和会议的现有测试套件补充定向回归。

交互验收在完整 App 窗口实际执行搜索、跳转、采用、改期和完成，并读回保存后的记录。真实模型的提取和问答先用虚构资料测试。最后用用户选定的一场日常会议验证跨天跟进。分别记录原生回归、真实模型样例和实际窗口操作的结果。

## 首版验收记录

- 隔离 App 宿主的 95 项原生回归中，92 项通过、3 项跳过。完整窗口里实际点击了「结束会议」、确认候选和完成待办。测试时钟跨日后，待办仍在今日简报可处理。宽窄窗口的定时任务入口及从简报打开保存结果也通过了点击验证。
- 使用 320 条虚构资料对照 24 个不同工单编号，索引结果均排在第一并显示命中原文。本次从查询到结果的 P95 由 27.04 毫秒降至 4.13 毫秒。定向回归另外核对了中文短词、正文中段定位和编辑后的索引更新。
- 普通 Debug App 构建通过。在独立工作区用实际 CLI 启动 App、创建虚构笔记和待办，核对了中文短词的原文段落定位，以及截止日期与安排日期分别筛选的结果。
- 后端 39 项定向测试通过。真实 Pi 用虚构资料提取出明确截止时间和对应原话，问答返回的来源编号及摘录也通过校验。真实日常会议验收需要选定会议后进行。

# 任务功能对齐：REA 分析、方案与实施

日期：2026-10-16。分支：`experiment/macos-native`。参考：本机 TickTick 8.0.80（滴答清单）。

继续实施的第二批内容为看板关闭任务归列及卡片内子任务，最新结果见文末“看板层级继续对齐”。首批记录保留其当时的测试结果。

## 证据与判断方法

本轮复用此前 REA 的任务 nib 解析，并重新通过 REA `inspect-native-dispatch-metadata` 读取当前已安装客户端，通过 `observe-native-ui` 保存运行界面。运行验证由 CUA 操作具名临时任务“REA 任务对齐 10-16”。源码比对使用当前工作区，已有实现不能仅凭旧报告判定已对齐。

- [本轮原生声明](audits/ticktick-tasks-2026-10-16/rea-task-declarations.json)：看板卡片正文/图标容器、单击/双击、子任务、关联主任务、标签、模板等入口；仅证明静态结构。
- [本轮任务界面](audits/ticktick-tasks-2026-10-16/ticktick-task-detail.png)及运行记录：任务三栏、正文、日期、优先级、子任务、清单归属。
- [本轮看板界面](audits/ticktick-tasks-2026-10-16/ticktick-task-board.png)：日期列有独立添加入口，列内创建继承当天日期，卡片带正文和紧凑元数据。
- 参考任务右键实测：日期快捷操作、四档优先级、添加子任务、关联主任务、置顶、放弃、移动、标签、专注、副本、链接、便签、转换笔记、删除。
- 参考 AX 导航包含已完成、已放弃、垃圾桶及已归档的清单。没有内容或按配置隐藏的入口并不一定出现在当前截图中，不能把 AX 中的节点等同于屏幕可见内容。
- `TTTaskDetailTopView.progressView` 只证明进度控件存在，未据此推断手动百分比进度功能。

## 本轮执行计划

1. **P1 操作闭环**：看板复用列表菜单与日期弹层，共用菜单补齐关联主任务和复制链接；显示设置对两种视图生效；确定目标的日期/优先级/清单/标签/自定义分组支持列内添加，创建时间不冒充安排日期。列属性提供默认值，显式输入的日期、优先级或清单保留优先权；这是与本项目共用快速添加保持一致的设计选择，尚未在参考客户端验证覆盖优先顺序。批量关联覆盖所有所选任务，合并禁用与失败状态正确，笔记转换一次撤销/重做覆盖整批。
2. **P2 状态视图**：增加独立“已放弃”导航、计数与按关闭日期分组；全局“已完成”仅显示已完成任务。恢复行为沿用已有动作，日期/搜索/详情共用。点击智能清单时清除活动过滤器，避免沿用之前过滤条件而漏显示任务。
3. **P2 过滤器可用性**：候选包括收集箱及保留的已选项；用正式过滤谓词生成草稿匹配预览，未保存不写库；打开已保存过滤器时，页面标题显示其名称。
4. **验证与交付**：新增跨入口和事务测试，运行原生工程完整测试；使用隔离验收数据检查看板、批量和状态导航，记录真实通过项与限制。

第二批已实施：已完成任务留在所属列的折叠小节、卡片内子任务展开。第三批继续实现清单归档与多标签看板，结果见文末。跨列拖放和参考端多标签分组的精确规则仍需后续核对。

后续顺序：补验参考端归档编辑权限及多标签分组规则 → 跨列拖放 → 独立标签及层级 → 高级过滤表达式 → 时间线。静态声明不替代交互验收。

## 看板层级继续对齐

本批聚焦两项已由 REA 运行截图确认的差距。[参考看板](audits/ticktick-tasks-2026-10-16/ticktick-task-board.png)显示：今天列标题统计 2 条未完成任务，下方另有“已完成 1”的可折叠小节；无日期列的父卡片在同一白色卡片内展开子任务，子任务有自身勾选框、正文和日期。本批复用该证据，不将静态类名当作交互证明。

实施方案及落点：

1. `TaskListProjection` 为看板按全部可见任务的原属性分列，列内再分开放和关闭区；列表及独立已完成/已放弃页沿用原有投影。工作区分组缓存包含视图形态，避免切换列表/看板后复用错误分组。
2. `TaskKanbanView` 列标题统计开放根任务，关闭区显示独立计数并支持折叠。即使最后一个开放任务完成，关闭任务所在列仍可浏览、恢复和继续创建；“隐藏已完成”会隐藏这些关闭任务。
3. `TaskKanbanCardView` 以同一任务树展开父子行，子任务保留原任务身份、顺序及共享折叠状态。子任务可独立选择、完成/恢复、改日期和使用右键菜单；动作继续走共享任务层，更新父任务进度并支持原有撤销。隐藏已完成也作用于卡片中的关闭子任务。

验证结果：新增 5 个用例；任务专项 **112 项通过，0 失败**。最新完整回归 **1323 项，1318 通过、5 跳过、0 失败**，覆盖本批全部代码。跳过项仍为 4 个需真实会议服务的集成测试及 1 个需要测试宿主成为前台应用的焦点测试。

隔离副本的 8 组原生流程全部通过：父卡片折叠/展开；子任务独立完成与恢复、进度更新和打开自身详情；子任务菜单改期、日期弹层确认保存及逐次撤销；最后一个开放根任务完成后留在原列；关闭小节折叠/展开；恢复后回到同列开放区及撤销；隐藏已完成同时作用于关闭根任务和子任务。验收后已恢复显示偏好、任务活动/完成状态，并清除临时子任务日期。

## 清单归档与多标签看板

本批先核对滴答 8.0.80 的归档确认框。运行界面明确说明：归档清单放入“已归档的清单”，其中任务或笔记不再出现在智能清单，到期也不提醒。说明框已取消，未实际归档普通参考清单。[REA 归档说明截图](audits/ticktick-tasks-2026-10-16/list-archive/ticktick-archive-confirmation.png)与[观察记录](audits/ticktick-tasks-2026-10-16/list-archive/verification.json)保留该事实。

本项目已实施：

1. 清单元数据新增可选 `archivedAt`，旧数据仍按未归档解码。归档与恢复都只修改清单状态，各占一个撤销步骤；保留身份、颜色、图标、置顶、原文件夹、自定义分组、任务正文及父子关系。SQLite 重载和迁移文件导出/导入都保留归档状态，包括没有任务的空清单。
2. 侧栏普通清单与“已归档的清单”分开显示；归档分组可折叠，归档清单可进入浏览。浏览页显示状态说明和“恢复清单”，隐藏创建栏与看板列内添加；右键也可恢复。进入清单时清除之前的过滤器，避免旧筛选条件导致归档内容看起来为空。
3. 智能清单、徽标、过滤器预览、日历、四象限及专注任务候选使用未归档清单的任务。创建和移动候选不包含归档清单。持久化继续保存清单全集，避免重启丢失空归档清单；任务链接能打开所属归档清单。归档、恢复、撤销和重做都重新核对提醒资格，既有任务上的日期与提醒设置保持原值。
4. 按标签分组的看板把同一任务投影到其各个标签列。卡片共享原任务身份、父子关系与动作，完成、恢复、改名和撤销会同时更新各列；关闭任务仍在各列原小节中。“无标签”列与列内创建继续使用既有规则。原生平铺列表仍保持一条任务一个行身份。

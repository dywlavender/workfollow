# 日期浮层锚点整改方案

日期：2026-10-02。范围是日期呈现、定位和关闭流程，不修改 TaskDateDraftModel、提醒/重复规则或提交通道。

## 明确的缺口

任务行日期入口绑定整行、Inspector 重复入口绑定整个 Header；四象限行、快速组合器和批量面板也绑定外层容器。旧测试只验证父框稳定，无法发现按钮与面板的初始距离错误。系统 Popover 迁为 NSPanel 后，不能再依赖系统猜测触发区域。

## 设计契约

- 日期按钮必须提供自己的 bounds。容器承载浮层时，通过有类型的 date / recurrence 锚点标记选取触发控件。
- 右键菜单的自定义日期保存本次右键点击坐标；即使任务没有日期，也不退回整行锚点。
- 日期主面板保持 260pt 宽。优先左缘对齐按钮，在按钮下方留 6pt 间隔；下方不足则翻上。仅越界时水平平移。
- 安全边界是所属屏幕 visibleFrame 内缩 8pt；原生子窗口允许越过主应用窗口边界。上下两边都不足时选择空间更大侧，再 clamp。该避让允许接近屏幕边缘时不严格贴按钮，但不能无条件对齐行首或 Header 首部。
- 主日期面板使用独立 schedule 定位策略，不改变 Context / More / 属性子卡片现有定位策略。
- 打开时间、提醒、重复子卡片不改变主面板尺寸；新增重复结束行仍允许向下增高。若增高越界，必须重新避让，不能遮挡 Footer。
- 输入框初始获焦；Esc 先子后父；取消与外部关闭不提交；确定仅一次提交，bulkSelection 不变。

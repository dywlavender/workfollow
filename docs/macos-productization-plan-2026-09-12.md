# 打勾 macOS 个人版：体验评估与改造方案

评估日期：2026-09-12  
目标分支：`feature/flutter-personal-desktop`  
范围：`desktop/` 的 Flutter 应用、macOS Runner、现有设计基线及个人数据迁移。  
交付性质：评估与实施方案；本次没有修改产品代码。

## 1. 结论与产品定位

这条分支已经有真正的 Flutter macOS 应用雏形，下一步应做产品化。任务和笔记的基本编辑、本地保存、个人数据导入、主题令牌、部分键盘操作已经建立，值得继续使用。

当前主要问题是：界面承诺的能力与实际行为不一致。提醒可以设置但不调度，重复规则可以保存但不会生成下一次任务，删除提示进入废纸篓但没有持久化废纸篓，保存状态也没有接到实际写入结果。继续增加页面或装饰会扩大这种落差。

**建议定位：一个随手记录、安排今天、连接工作资料的个人 Mac 工作台。** 核心价值是把“记下来 → 安排 → 执行 → 回到相关笔记”串起来。轻量、离线、无需登录沿用现有定位。

本方案按“首先给自己长期使用，随后可以分发给其他 Mac 用户”规划。团队协作、账号和实时同步不计入首个完整版本；这来自当前分支的产品边界，而非对所有 Mac 应用的通用判断。若目标改为多人协作，需另行调整数据与同步设计。

有两项前提需要修正：

1. **沿用 Web 的业务概念，不等于照搬 Web 的导航列数。** 旧设计把“全局导航＋任务导航＋列表＋详情”作为基线，但个人版的模块更少，应允许合并导航，把空间还给内容。
2. **Flutter 编译成 Mac 应用，不代表所有控件已经符合 Mac 习惯。** 目前大量交互仍是 Material 弹层和自绘控件。建议保留 Flutter，集中补足系统菜单、窗口、输入和通知；没有证据支持现在投入一次完整 SwiftUI 重写。Flutter 官方也提供适配 macOS 外观与系统能力的路径。[依据](https://docs.flutter.dev/platform-integration/macos/building)

## 2. 评估方法与证据范围

- 阅读全部桌面端主要页面、控制器、模型、存储、Runner 和两个现有测试文件，并与 `docs/macos-personal-app-design.md` 对照。
- 运行 `flutter test`：现有 **10 个测试全部通过**，主要验证页面展示、基础编辑和迁移合并。
- 使用临时行为探针检查实际代码：**6 项观察得到复现**，包括清单内新建错位、无日期稍后任务序列化后归组变化、日历数据源为空、重复任务无下一次、笔记正文与结构化内容不同步、设置快捷键切换主题。
- 第 7 项搜索流程探针在打开命令面板时遇到 `No Material widget found`，尚未走到点击结果阶段。笔记搜索不定位的结论来自事件处理代码，不能声称已经完成该端到端验证。临时探针已移除，未留入产品测试集。
- `flutter analyze` 未完成：分析服务在解析初始化消息时发生 `FormatException` 并退出。此项记为工具链检查未通过，不能归结为已确认的业务代码错误。
- 本机界面读取因辅助功能／屏幕录制权限未就绪而未完成。本报告的布局判断来自组件结构和尺寸计算，**不把它写成已完成的视觉验收**。没有重新验证 release 构建、通知实机投递或一万条数据性能。

以下“事实”是源码或探针能确定的现状；“建议”是产品取舍；时间和性能数字均为拟定目标，不是现状测量结果。

## 4. 必须改进的问题

P0：进入长期自用前修复，影响操作结果与数据可信度。  
P1：首个完整版本内补齐，影响流程效率和产品成立。  
P2：核心流程稳定后增强。

### 4.1 P0：用户看到的结果必须是真的

| 问题与事实 | 对用户的影响 | 改造与验收 |
| --- | --- | --- |
| **新建任务不继承当前清单。** `quick_add.dart:41` 只传标题；`workspace_controller.dart:516` 默认创建到收集箱、bucket 为今天，且没有 dueAt。探针复现。 | 在“工作”清单按 Return，任务看起来消失；收集与安排混为一件事。 | 新建命令显式携带当前清单、日期和来源。工作清单新建后立即留在该清单；收集箱默认无日期；今天新建明确安排今天。 |
| **今天与日期逻辑不可靠。** `models/task.dart:171` 将无日期归入今天；bucket 存在模型中，恢复时重新计算；无日期“稍后”任务往返序列化后变今天。 | 今天被未安排事项淹没；重启前后视图可能不同。 | 以日期和状态计算视图，统一无日期语义，跨日/唤醒更新。全天日期与具体时刻分开；导入 UTC 时刻后按本地时间显示与归日。 |
| **“已自动保存”是固定文案。** `task_inspector.dart:292`、`notes_screen.dart:588` 未订阅存储结果；`_schedulePersist` 异步触发保存；设置把工作快照称为最近备份。 | 用户无法判断内容是否已落盘，也会误以为有可恢复的历史副本。 | 增加保存中/已保存/未保存状态；完成写入才显示已保存。备份有独立文件与时间记录；关闭/退出时处理未完成保存。 |
| **没有真正的废纸篓。** `removeTask` 从列表移除，只留一次内存撤销，却提示移到废纸篓；`removeNote` 直接移除。 | 删除后重启无法从产品内找回；连续删除只能撤回一项。 | 任务和笔记统一软删除，废纸篓持久化；支持恢复原清单/文件夹；永久删除放在废纸篓内。提供连续操作撤销。 |
| **日历没有接入真实任务。** `calendar_screen.dart:135` 读取 visibleTasks，而日历视图返回空数组；计数函数还保留固定日期的示例逻辑。点击日期只改选中颜色。 | 有截止日期的任务不一定出现在日历里，不能用于安排工作。 | 改为独立日期查询。某日显示数量与当日列表一致；点任务打开详情；修改安排后列表、今天、日历同步更新。 |
| **搜索入口本身需要修复。** `command_palette.dart:210` 的 TextField 在当前弹层中没有 Material 祖先，探针打开即报错；笔记结果事件只 selectView(notes)。 | 最快的查找入口可能失败；即使匹配成功，也不能保证打开目标笔记。 | 先修弹层结构；统一 `openTask(id)` / `openNote(id)` 导航；搜索第二条笔记后编辑器必须显示第二条。 |
| **正文存在两份不同版本。** `updateNoteBody` 更新 plainText/preview，不更新导入的 contentJson；探针复现。 | 当前纯文本看似已编辑，后续富文本渲染或导出可能继续使用旧正文。 | 明确唯一正文来源与内容格式版本。结构化正文生成纯文本索引；在富文本编辑器接入前，也必须定义纯文本编辑后的转换/保留策略，不能静默分叉。 |

存储实现还有一个直接关联的问题：`LocalWorkspaceStore.save` 的串行 Future 链没有错误恢复，前一次写入失败后后续写入可能继续被失败链阻断；读取失败又与“首次没有数据”同样返回 null。修复时需要区分空工作区、加载中和读取失败，保留原文件并提供重试/恢复入口，避免直接回到示例数据后继续保存。这里应做一次完整修复，无需扩展成大量罕见场景测试。

### 4.2 P1：把功能入口接成完整流程

| 问题与事实 | 改造方向 |
| --- | --- |
| 提醒/重复目前只是字段；完成重复任务不生成下一次；日期弹窗只能选日期，缺少完整时间编辑。 | 接入系统通知、日期＋可选时间、提前提醒；提供每天/每周/每月的真实重复计算。设置提醒时展示授权状态。 |
| Cmd-, 切主题；Cmd-N 先跳今天再开搜索；任务行 Return 与 Space 都勾选完成。 | Cmd-, 打开设置；Cmd-N 直接进入当前上下文新建；Return 编辑/打开，Space 完成；文本输入时保留编辑快捷键含义。 |

| 今天列表中逾期组没有排除已完成任务；首页 doneToday 实际统计全部已完成。 | 所有页面复用相同查询规则；今日完成仅统计今天 completedAt；完成任务不能同时出现于逾期和已完成组。 |
| 子任务 UI 是三条固定示例；附件是展示字段；没有桌面端任务—笔记关系实现。 | 建立真实子任务与附件实体，支持增删改和完成；笔记选中文本生成任务，任务保留来源链接，笔记显示关联任务状态。 |
| 笔记全文搜索只查 title/preview/folder，preview 最多约 110 字；文件夹存在 parentId 但显示/合并逻辑按名称处理。 | 搜索完整正文；先提供一层稳定文件夹与管理操作；导入层级要保留结构或明确展示转换结果，不能按重名静默折叠。 |
| 设置导航项是静态展示，季节开关只改面板局部状态，主题不跟随系统也不持久化。 | 设置页只出现可使用的选项；外观/提醒/数据/快捷键真正可切换，偏好即时生效、重启保留。 |
| macOS 菜单仍主要是模板；关闭最后窗口即退出；应用名称与标识仍是工程占位。 | 接通原生命令菜单；定义关闭窗口、后台录入、明确退出的行为；应用显示名、图标、标识与系统版本范围统一。 |

### 4.3 P2：后续有价值，但不抢占首版

- 自然语言日期录入：先支持“明天下午三点”，提供解析预览与取消；先验证常见输入，再扩展复杂句式。
- 多窗口笔记、Spotlight、Shortcuts 和外部深链。
- 专注计时、周回顾和简单完成统计；优先帮助规划，不增加复杂报表。
- 云同步、AI/Agent 接入：等本地数据模型、内容来源与撤销稳定后另立方案。当前不移植 Web 的团队权限、审批与协同系统。

## 5. 建议的交互与页面结构

### 5.1 导航收敛为三栏

建议保留“今天、计划、日历、清单、笔记”等熟悉名称，合并重复的全局与二级导航。首页可以保留为可选概览，默认恢复上次位置，首次进入今天；不要求用户每次先经过一屏卡片。

```text
任务模式
┌──────────────────────────────────────────────────────────────┐
│ 系统标题栏／工具栏    当前视图    搜索    筛选    新建            │
├──────────────┬──────────────────────────┬────────────────────┤
│ 统一侧栏      │ 今天／计划／当前清单      │ 所选任务详情         │
│              │                          │                    │
│ 收集箱        │ 快速添加                 │ 标题                │
│ 今天          │ 逾期（可折叠）           │ 安排／截止          │
│ 计划          │ 今天任务                 │ 描述与子任务        │
│ 日历          │ 已完成（可折叠）         │ 相关笔记／附件      │
│ 清单…         │                          │ 其余属性折叠        │
│ 笔记／文件夹… │                          │                    │
│ 废纸篓        │                          │                    │
└──────────────┴──────────────────────────┴────────────────────┘
笔记模式：统一侧栏／文件夹 → 笔记列表 → 编辑器
日历模式：统一侧栏 → 月历 → 选中日期的日程列表
```

尺寸是第一轮验证起点，不是未经实测就冻结的规范：

| 窗口可用宽度 | 布局建议 |
| --- | --- |
| 1180 pt 及以上 | 三栏；侧栏约 210–230，详情约 320–360，其余给列表；拖动分隔线调整 |
| 900–1179 pt | 侧栏可收起，列表＋详情优先；笔记优先保证编辑宽度 |
| 680–899 pt | 双栏或单内容区；Return/单击进入详情，返回后恢复列表选择与滚动位置 |

第一轮同时验证 1280×800、1024×720、880×600，以及 MacBook 常见半屏宽度；确认高频流程成立后再决定最小窗口。原生窗口应允许缩放，侧栏应该可显示/隐藏，并在菜单中可发现。[Apple 窗口与输入指导](https://developer.apple.com/design/human-interface-guidelines/designing-for-macos/)、[侧栏指导](https://developer.apple.com/design/human-interface-guidelines/sidebars?changes=_11)

### 5.2 记录：在当前上下文一次完成

- 收集箱：输入标题，Return 保存，无需日期、优先级或清单选择。
- 今天：新建默认安排今天，清单可先归收集箱，日期以可见标记呈现。
- 自定义清单：新建继承清单，无日期保持未安排。
- 日历：选定日期后新建继承该日期。
- 笔记：Cmd-N 新建当前文件夹笔记；Cmd-Shift-N 始终新建笔记。菜单名称跟随上下文变化。
- 菜单栏快速录入：可配置全局快捷键打开轻量输入窗；Return 后关闭并把焦点还给原应用。首次启用由用户选择快捷键，处理冲突。
- 命令面板搜索与快速录入共用命令逻辑，但使用独立清晰入口；不再通过创建“未命名任务”逼用户二次找到它。

### 5.3 安排：区分打算做与必须完成

建议模型拆开“安排日期”和“截止时间”：今天表示要做的工作，截止表示约束。旧数据的 dueAt 原意保留，不因为用户点“今天”就篡改截止时间。

- 今天＝安排今天的任务＋今天截止且未完成任务；逾期单独分组并排除已完成。
- 收集箱＝归属收集箱的未完成任务，允许有日期；未安排通过独立过滤查看。
- 计划＝未来已安排或有截止日期的任务，按日期分组；同一任务去重，标明时间信息来自安排还是截止。
- “移到今天”只改安排，延期截止提供独立命令。
- 日历展示对应日期的真实任务；拖动默认改安排日期，截止时间单独编辑；全天项目不显示假的 00:00。
- 日历数据查询不依赖当前导航筛选，切页面不会导致日程消失。

如果首版不拆日期字段，也必须先统一单日期的文案与行为，并明确“移到今天”会改变什么。推荐拆分，因为当前混用已经影响核心认知。

### 5.4 执行：列表操作完整、详情保持轻量

- 行内完成；Return 打开标题编辑或详情；上下键移动选择；Shift/Cmd 多选；右键与菜单提供相同操作。
- 完成、改日期、移动、删除支持撤销；编辑文本时 Cmd-Z 撤销文字，列表聚焦时撤销任务操作。
- 拖动直接跟随鼠标，显示插入位置；可移入清单/日期；保留键盘与菜单替代方式。
- 提醒首次使用时请求通知权限，后续可查看权限状态；完成、删除、改时间同步更新系统通知。授权应在相关操作发生时提出。[Apple 通知授权指导](https://developer.apple.com/documentation/usernotifications/asking-permission-to-use-notifications)
- 系统通知负责已登记提醒的投递，不能只依赖进程内计时器；点击通知直接打开对应任务。后台或退出后的投递与应用生命周期分开处理。[Apple 本地通知说明](https://developer.apple.com/library/archive/documentation/NetworkingInternet/Conceptual/RemoteNotificationsPG/SchedulingandHandlingLocalNotifications.html)
- 首版重复提供固定周期：每天、每周指定星期、每月指定日期；月末规则在界面说明。完成一次保留历史并创建下一次；撤销时同步恢复。按完成时间延后 N 天可后续添加，不与固定周期混在一个字段。

### 5.5 笔记：围绕行动形成区别于普通记事本的价值

建议以“会议记录 → 选中行动项 → 创建任务 → 执行后返回记录”为第一条完整联动链。

首版编辑支持正文、标题、粗体/斜体、列表、勾选列表、引用、链接和代码块；能粘贴图片、插入附件。任务详情显示相关笔记；笔记侧显示关联任务及完成状态。转换行动项不删除原文，也不在两个位置维护两份任务。

先用真实 Web 笔记验证富文本转换，尤其是列表、链接、图片和任务引用。选择 Flutter 编辑器前做小型验证，不直接因为某个库提供工具栏就确定技术路线。不支持的内容保留原结构并在迁移预览中说明，而非静默损失。

已有编辑器底部的固定宣传语、存储实现说明移至欢迎/帮助或设置，正文区只保留与写作有关的信息。自动保存反馈只在状态变化或失败时出现，无需每页常驻云图标暗示同步。

### 5.6 视觉：保留克制方向，先修比例和状态

- 沿用现有中性内容背景、单一强调色、语义令牌，先不重新设计全部品牌。
- 普通界面文字以系统字体 13–14 pt 为起点；笔记正文 15–16 pt，可调整。行高、中文输入和长标题以实测定稿。
- 减少重复页标题、大段空状态文案和纯装饰卡片；让标题、日期、完成状态具有稳定优先级。
- 季节只影响低信息区域；关闭后实际移除装饰。增加跟随系统、减少动态效果和持久化偏好。
- 属性编辑优先锚定弹出框、下拉菜单或适当的窗口附属面板，避免日期、优先级和清单连续打开底部抽屉。
- 保留已有任务行和侧栏的焦点、语义基础，扩展到搜索、设置、日历与所有图标按钮。VoiceOver、对比度和减少动态效果在实机完成验收，不因使用 Flutter 控件就视作已支持。

## 6. 技术改造边界

### 6.1 渐进调整，不重写整个应用

| 层次 | 建议职责 | 对应改造位置 |
| --- | --- | --- |
| 视图 | 三栏布局、选择、焦点、滚动恢复、局部编辑状态 | `app.dart`、`screens/`、`widgets/` |
| 导航与命令 | 新建上下文、按 ID 打开、菜单/快捷键共用行为、撤销 | 从 `workspace_controller.dart` 提取导航及命令服务 |
| 业务模型 | 任务、日期、重复、子任务、笔记、关系、删除状态 | `models/`，新增日期与重复规则模块 |
| 本地存储 | 事务写入、查询、全文搜索、格式版本、备份恢复 | 替换 `local_workspace_store.dart` 的正式存储路径 |
| Mac 集成 | 文件选择、通知、菜单栏入口、快捷键、窗口偏好 | `macos/Runner/`＋明确的 Dart 平台服务接口 |

现有约 947 行的 WorkspaceController 同时管理演示数据、所有实体、导航、迁移和持久化，后续任何编辑都会通知整个工作台。应按职责逐步拆分，先保证正确，再用测量决定哪些列表/编辑器需要减少重建。

### 6.2 本地存储的建议

当前 JSON 足以做原型，先修保存状态和恢复语义。正式版建议使用 SQLite：任务、笔记、文件夹、子任务、附件引用、关联关系以及删除状态可以事务更新，也更适合全文检索与按日查询。JSON 保留为可读的导入导出格式。

建议最小模型包含：

- Task：稳定 ID、listId、标题、正文、安排日期、可选截止时刻、完成/删除时间、排序位置。
- Recurrence：规则与系列 ID；每次完成实例可查询。
- Subtask：parentTaskId、内容、完成状态、排序。
- Note：稳定 ID、folderId、内容格式版本、正文、派生的 plainText、更新/删除时间。
- TaskNoteLink：taskId、noteId，以及可选来源段落定位。
- Attachment：相对文件路径与资源引用；清单和文件夹按 ID 关联，改名称不改变归属。

备份先做易理解的最小版本：每天首个有效修改后生成一个独立副本，保留最近 7 份；支持“立即备份”、选择目标文件夹、显示最近成功时间、导入恢复预览。该保留策略是建议默认值，可在使用后调整。数据库与附件必须形成一致的恢复集合；实施 SQLite 后使用一致性备份方式，不直接复制活跃数据库文件。

迁移顺序：保留旧文件 → 解析与预览 → 在新存储中事务导入 → 校验数量、正文和关联 → 切换读取。现有按相同 ID 跳过的合并策略继续可用，但把新增/跳过/缺失附件的数量讲清楚。首次导入应能选择空白工作区，演示数据以独立试用入口提供，不能混入用户正式数据。

### 6.3 Mac 集成与分发

- 菜单、快捷键、工具栏调用同一组命令，避免出现显示可用但没有接线的菜单项。Apple 强调菜单可发现性与熟悉的交互行为。[菜单指导](https://developer.apple.com/design/human-interface-guidelines/menus?changes=_4_1_8)
- 默认关闭窗口后允许通过 Dock 再次打开；启用菜单栏录入时保留后台入口；Cmd-Q 明确退出。已登记通知的系统投递独立验证。
- 原生文件面板读取与导出需要验证 release sandbox 的用户所选文件权限。目前 entitlements 未声明相关文件读写权限，Debug 能选中文件不等于正式包已验证可导入。[Flutter macOS 文件权限说明](https://docs.flutter.dev/platform-integration/macos/building)
- 若分发给他人，再完成稳定应用标识、中文显示名、应用图标、签名、公证、安装包与更新路径；个人自用阶段无需先建设自动更新服务。对外分发要求按当前官方流程验证。[Flutter 分发说明](https://docs.flutter.dev/platform-integration/macos/building)
- 旧文档的系统下限为 macOS 15，Runner 部署值为 10.15。选定实际支持范围后同步文档与构建配置，并用该范围的系统验证，不能只改数字。

## 7. 分阶段实施计划

| 0：验证边界 | 用真实任务/笔记确认日期语义；三种窗口布局；富文本兼容小样 | 冻结新建/今天/日历规则与导航草图；列明支持的笔记内容 | 1–2 人日 |

## 8. 验收场景与度量

这些是改造后的验收目标，尚未测量达成。选定一台参考 Mac，统一 release 构建、数据规模和窗口条件记录结果。

| 场景 | 通过条件 |
| --- | --- |
| 冷启动与继续工作 | 本地工作区首屏可交互目标 ≤2 秒；恢复上次视图、所选项与窗口；不闪出演示数据 |
| 快速记录 | 应用内标题＋Return 即保存；外部快捷键唤起目标 ≤500 ms；成功后返回原 App |
| 上下文一致 | 工作清单创建留在工作；收集箱无日期不自动占用今天；日历指定日期新建不丢日期 |
| 安排与完成 | 今天/计划/日历数量与任务一致；跨午夜或睡眠唤醒后正确更新；全天日期和具体时刻显示清楚 |
| 编辑与恢复 | 输入中文不丢字、不抢焦点；等待保存完成后重启内容一致；任务和笔记删除后重启仍可恢复 |
| 重复与提醒 | 完成重复任务生成下一次；撤销可恢复；修改提醒能更新系统登记；关闭主窗口后实机检查投递 |
| 搜索 | 1 万任务＋1000 笔记下，输入停顿至结果更新目标 p95 ≤200 ms；能搜到长笔记后半段；打开的正是匹配项 |
| 三种窗口 | 1280×800、1024×720、880×600 可完成创建、编辑、安排、查找；半屏下有明确的详情/返回流程 |
| 完整键盘流程 | 不使用鼠标完成新建、选择、编辑、安排、完成、撤销、搜索、打开设置；编辑文本与列表命令不冲突 |
| 笔记联动 | 选中行动项生成一个任务；笔记保留引用，任务可回到来源；完成状态双向一致 |
| 数据迁移与备份 | 使用真实内容样本对照标题、正文、日期、清单、层级、图片/附件；备份恢复到独立工作区结果一致 |
| 外观与辅助功能 | 浅/深/跟随系统均可读；季节开关实际有效；VoiceOver 能识别控件与状态；减少动态效果生效 |

新增自动测试应围绕上述跨页面、持久化和日期行为，修复命令面板打开即报错等已有遗漏。保留真实通知、菜单、文件权限、中文输入、拖拽和窗口行为的实机验证；页面能显示和模型能赋值不足以替代这些检查。

# 本地资料问答与笔记 AI

## 使用

- 点击左侧搜索按钮，或按 `⌘K`，输入问题后点击“问 AI”。例如“海鸥项目还有哪些未完成任务”“海鸥上次会议定了什么”。普通回车仍用于打开搜索结果；进入问答后回车提交新问题。
- 回答下的来源卡片同时显示原文摘录。点击打开对应任务、笔记或会议发言；底部反馈中的“返回问答”可回到原回答。
- 笔记顶部的“AI”菜单提供整理要点、润色笔记、提取待办。前两项先生成可编辑草稿，点击“保存为新笔记”后才创建结果，正文附原笔记链接。提取待办继续使用候选确认页。
- 会议对话记录右上角可按正文、讲话人或 `01:20` 这样的时间查找。问答引用的定稿发言会滚动定位并高亮。

## 实现边界

资料来自未删除、未转换及未放弃的任务、未删除笔记、会议纪要及定稿发言；不处理转写草稿、图片识别或附件二进制。任务状态、重要性、安排日期、截止日期直接来自业务数据，笔记中的描述不会改变任务状态。

检索在后台读取不可变业务快照，先复用 `NativeDocument.matches` 排除无关正文，再分段排序。不会在每次键入时扫描完整资料。当前是关键词与分词检索，词义不同但语义相近的内容可能遗漏；结果是本次选取资料的综合回答，不是全库统计。只有明确提交问题才发送选出的文字片段给当前文字模型。

每次选取最多 8 处、每处不超过 2400 字符的资料。Native 不向 AI 后端提供写业务数据的工具；后端统一维护 `knowledge.ask`、`note.rewrite` 提示词，兼容本机 Pi、OpenAI 兼容 Chat Completions、OpenAI Responses。直接调用会按配置的上下文预算进一步收缩资料，返回实际使用的来源编号。引用必须指向传入资料，摘录必须与原文连续匹配；这能验证引用存在，不能替代对回答含义与推理正确性的核对。

文字操作统一按一轮对话处理。Pi 模式走正常 Agent RPC，使用本机模型与认证，采用工作助理场景提示词；上下文、压缩和服务重试交给 Pi。笔记整篇提交，不按字节估算 token、不预先拆段、不维护续接缓存，也不另设 Pi 输出上限。直接调用模式使用 LangChain Agent 和框架自带的会话管理，同样不在应用侧截取、分段或自行合并正文。

待办、笔记、资料问答、摘要和文字纪要都接收正文流。待办及问答只投影人能阅读的标题或回答，不展示未完成 JSON；最终结构、原文依据和来源仍须校验。笔记和待办需用户确认后才保存，摘要保留原来的草稿对照；会议纪要只在整轮生成完成且期间没有手动修改时替换。

生成中可以停止。Pi 压缩和重试会显示状态，并等待 Agent 的 `agent_settled` 后才将本轮视为结束；普通 `agent_end` 不代表压缩或恢复已经结束。正文持续返回时刷新等待时限，压缩阶段交给 Agent 处理。应用只保留操作互斥、取消、错误提示和限流等待，不额外再跑一套 Agent 重试或压缩流程。

会议转写仍使用现有语音模型，没有新增讲话人分离模型。本轮修复了二次整理的依据选择，保留本地录音、五分钟定时、手动互斥和编辑保护；识别准确率、断句和多人区分尚未经过新的实录对照。

## 开发入口

- `KnowledgeRetrieval.swift`：本地资料投影、中文检索、状态 / 时间过滤和资料预算。
- `KnowledgeAnswerSession.swift`：取消、重试和过期响应处理。
- `KnowledgeAnswerView.swift`、`CommandPaletteView.swift`：问答与来源打开。
- `NoteRewriteComposerView.swift`：笔记草稿确认。
- `backend/app/ai_runtime/workflows.py`：场景规则及引用验证。
- `backend/app/services/ai_service.py`：直接调用预算和长文处理。

AI 模型沿用[模型配置](native-direct-model-settings.md)。当前没有配置文字模型时，失败界面可以直接进入设置，不会切换到其他模型或修改 Pi 配置。

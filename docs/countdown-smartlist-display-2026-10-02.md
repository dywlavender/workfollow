# 「显示」落地：倒数记录进入智能清单的「倒数纪念日」小节（2026-10-02）

> 对应 `docs/countdown-declared-vs-actual-2026-10-02.md` 的 **#2**。
> 那条的判据原来是「`smartListDisplay` 全仓只有 2 处引用，无消费方」——
> 现在它有消费方了：**决定这条记录进不进「今天」清单**。

---

## 一句话结论

`smartListDisplay` 从「存了但没人读」变成了真的判据。倒数记录现在会以
**自成一节**的形式出现在「今天」清单顶部：标题 = 模块名 + 条数，
行 = 图标 + 名称 + 右对齐的相对日标签，**没有勾选框**。

真机验证过：默认档（当天显示）的记录出现在今天，`一直显示` 的记录带着
「127 天后」也在，`提前 7 天显示` 但落点在 127 天外的记录**没有**出现。

---

## 参照实现长什么样

证据：`docs/screenshots/ticktick-reference/18-countdown-in-today-group.png`
（临时建了一条落点=今天的记录后截的，看完已删）。

```
⌄ 倒数纪念日  1                      ← 自成一节，标题 = 模块名 + 条数
    [圆形图标] 审计临时-102    今天   ← 行 = 图标 + 名称 + 右对齐的相对日标签
⌄ 已过期  8                          ← 任务组照旧
    ☐ …                             ← 任务行才有勾选框
```

三个可直接照做的点：

1. **自成一节**，不混进任务组；标题样式与任务组头一致（半粗 + 条数）；
2. 行 = **图标 + 名称 + 右对齐的相对日标签**，标签是**强调色**（参照图里是蓝色）；
3. **没有勾选框**——它不是任务，不可完成。

`docs/screenshots/ticktick-reference/12-countdown-display-dropdown.png` 给了
「显示」的五个选项：分组标题「在智能清单中」+ 当天显示 ✓ / 提前 3 天显示 /
提前 7 天显示 / 一直显示 / 不显示。默认是「当天显示」。

## 取舍（明确标注，不是「已对齐」）

参照图只观察到**一态**（当天显示 + 落点就是今天 + 在今天清单里）。
下面这些是**没有参照可对**的地方，我按最直接可辩护的读法实现，逐条列出：

| # | 取舍 | 为什么这么选 |
| --- | --- | --- |
| 1 | **只做「今天」这一支**。最近 7 天 / 所有 / 收集箱等其它智能清单不铺开 | 参照图只在「今天」清单里观察到它。其余清单长什么样没看过——上一轮「备注入口」就是照着猜的样子铺开才出的错 |
| 2 | 「提前 3 天显示」= 窗口 `0…3`（共 4 天），不是「只在第 3 天那一天」 | 字面是「提前 N 天**开始**显示」，即从 N 天前一直到当天 |
| 3 | **过期的落点一律不进清单，含「一直显示」** | 参照图没观察到过期记录。「一直显示」若把一条早就过完的单次记录永远挂在今天，代价明显大于收益。重复类记录的落点永远在未来，不受影响 |
| 4 | 右侧标签：`今天 / 明天 / N 天后 / 昨天 / N 天前` | **只有 0 天那一态有参照（「今天」）**。其余照同一份参照图里任务行的相对日口径取（任务行写的是「昨天」），没有用绝对日期 |
| 5 | 行可点，点了跳到倒计时模块（不选中具体那一条） | 参照行为没观察过。但一行点下去没反应比「跳错地方」更糟，所以给了个明确去处 |
| 6 | 小节可折叠 | 参照图里「倒数纪念日」标题左边**有折叠箭头**，与「已过期」同款，所以折叠是合理推断；但没实测过它在参照实现里的折叠行为 |
| 7 | 小节排在**所有任务组之前** | 参照图里它在「已过期」之前。**置顶组的情况没观察到**——若今天有置顶任务，参照实现是把它放置顶前还是后，无从判断 |

### 真机证据（截图 + 无障碍读数互证）

跑在 `/tmp/wf-dd-display/Build/Products/Debug/WorkFollow.app`（pid 31690），
`--wf-destination today`。

截图：`docs/screenshots/countdown-smartlist-2026-10-02/01-today-with-countdown-section.png`

```
⌄ 倒数纪念日  2
    [🎂] 小美                今天
    [🎁] 春节              127 天后
⌄ 已过期  14                顺延
    ☐ 归纳高频问题  工作  9月24日
```

无障碍读数（`ax find`，坐标为全局屏幕点）：

```
AXButton desc="倒数纪念日 2"      @73,191 400x30   ← 小节标题 + 条数，高 30（= groupHeaderHeight）
AXButton desc="小美，今天"        @65,221 416x36   ← 第一行，高 36（= countdownRowHeight）
AXButton desc="春节，127 天后"    @65,257 416x36   ← 第二行
```

四条断言都成立：

1. **位置**：小节标题在 y=191，任务组「已过期」在它下面 → 小节在任务组之前；
2. **顺序**：0 天（小美）排在 127 天（春节）之前 → 近的在前；
3. **窗口**：落点 127 天外的记录没被「提前 7 天显示」放进来 → 窗口判据真的在起作用；
4. **无勾选框**：小节里的行都是 `AXButton`，没有 `完成：xxx` 那种勾选框元素
   （任务行才有，见截图下半部分）。

另外验了两个自己加的行为：

- **折叠**：点小节标题 → `小美` 从树里消失、标题仍在；再点一次 → 回来；
- **点击行**：点「小美」这一行 → 页面切到倒计时模块（页头出现「所有 / 纪念日」
  筛选胶囊，`小美` 卡片读数变成 `还有 0 天`）。

### 数据卫生

真机验证需要一条**落点=今天**的记录，而库里两条记录都落得很远（小美 348 天、
春节 127 天）。经与用户确认的做法是**临时改真实数据、看完还原**：

- 改动：`小美` 生日 `9/15 → 10/2`；`春节` 的「显示」→ `always`（为的是让第二节行出现，
  顺带验证「一直显示」档与排序）；
- 备份：`/tmp/countdowns.backup.json`，sha256 `75487dc2fb00…`；
- 还原后 `cmp` 报**字节一致**，内容回到 `小美 9/15 / 春节 sevenDaysBefore`；
- 另一个会话的实例（pid 28639）全程没被碰过，也没有被 kill。

**没做成的一步（记下来）**：本想用 `open --env HOME=/tmp/…` 把数据目录整个隔离，
结果**没生效**——`FileManager` 的 `.applicationSupportDirectory` 走
`NSHomeDirectory()`（取 passwd 里的家目录），**不认 `$HOME`**。所以那一次跑的是真实
数据目录，第一轮「小节没出现」正是这个原因（两条记录的落点都太远）。
下次要么改 `NativePreviewRepository.directory`，要么直接接受「临时改真实数据 + 还原」。

## 没做 / 没验的

- **其它智能清单**（最近 7 天 / 所有 / 收集箱）里不显示——见取舍 #1，**没实现**。
- **点行不选中具体记录**，只跳到模块——见取舍 #5。
- **置顶任务与小节的先后**没判定——见取舍 #7。
- 参照流程里那条没碰过的差异仍在：添加是**两步**（第二步「样式」= 预览卡 + 卡片样式
  缩略图 + 颜色，按钮「返回 / 保存」）。
- **勘误（2026-10-02 复核）**：早先记的两条都不准——
  ②「第一步有一行『天数计算方式』」**不存在**：参照的「添加」只有六项，那个字符串
  （`day_calculation` = `天数计算\n方式`）属于**任务「日期」面板**，被误读了；
  ①里的「5 个卡片样式 + 20 个颜色」也不准：缩略图是**横向可滚动**的（可见 4 个半，
  第 5 个被面板右沿裁掉），颜色是「无颜色 + 12 个实色 + 自定义彩虹」共 14 格。
  逐项证据见 `countdown-note-entry-fix-2026-10-02.md` 的勘误段。
- **提交边界**：这份改动在共享工作树里与另一个会话的在途改动**同文件**。
  提交时按「只提交自己的改动」构造了 HEAD + 本改动的版本，**不含对方任何一行**；
  为不依赖对方尚未提交的新类型（`TaskEmptyStateView`），提交版里空态仍用 HEAD 原有的
  `Text(...)` 写法。工作树里则是两者合并后的版本。

# 会议纪要 skill 试用验收

## 实施范围

规则：`.pi/skills/meeting-minutes/SKILL.md`。

实验扩展显式读取规则，注入既有 `/wf-meeting-minutes` 输入；所有模型调用仍经 Pi。使用三轮虚构文字转写，未发送音频、未使用麦克风、未修改正式会议流程或全局 Pi 配置。

执行：`node macos-native/scripts/accept-meeting-minutes-skill.mjs docs/meeting-minutes-skill-trial-2026-10-06.json`。

## 实际结果

逐轮输入及完整模型输出保存在同名 JSON 报告中。

1. 初始决定：周五交付、预算三千元；正确列入已确认决定，交付负责人待确认。
2. 明确修正：下周一交付、预算两千五百元；当前决定更新，旧值仅保留为历史讨论。小李整理清单、下周一期限正确保留。
3. 新增未明确事项：保留第二轮决定及行动项；校对方案负责人、期限均待确认；投影仪提议留在待确认，不写成已确认采购。

人工检查以上语义通过。单轮延迟为 9.669 / 11.599 / 5.940 秒，包含 Pi 请求和模型响应，不代表音频转写延迟。没有相同输入的无 skill 对照组，因此不能据此量化 skill 带来的提升。

## 校验与限制

- Node 脚本语法校验通过；Pi 自带 `loadSkillsFromDir` 实际加载一项 skill，零诊断。
- skill-creator 的 Python 校验脚本因运行环境缺少 PyYAML 无法执行，未安装额外依赖；使用实际目标 Pi 的加载器校验。
- 本次是明确注入规则的行为测试，不证明 Pi 普通会话会自动发现/加载 skill。
- 尚未覆盖无实质新增时保持原纪要、用户手工编辑与 AI 更新冲突、长会议内容规模。
- 不验证音频识别、跨片段讲话人身份或真实线下会议质量。
- 正式接入时应明确加载同一份规则，不复制成另一份提示词；不把 skill 当作音频适配器。

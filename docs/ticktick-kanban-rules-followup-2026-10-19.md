# 看板规则核实与重复实例一致性

日期：2026-10-19。分支：`experiment/macos-native`。本批继续核实跨标签列、重复任务和子任务拖放，先修复不依赖参考端猜测、已经复现的本地数据不一致。

## 已确认的本地问题与修复

每日低优先级任务拖到高优先级列后，当前卡片变高优先级，但明天虚拟实例仍为低优先级；完成今天后生成的同一个明日实例又变高优先级。从“计划”移到“评审”分组也有相同问题：未来预览仍在计划，完成今天后下一次实际进入评审。

两个定向案例已分别复现上述差异。原因是未来投影读 `series.template`，完成生成下一次任务时则继承当前任务；优先级和分组动作只改了当前任务，遗漏模板。已有标签、标题及清单写入会同步相应模板属性，本批沿用这一既定本地语义，不将其描述为滴答看板的已确认规则。

修复集中在 `TaskActions`：优先级的单项及属性编辑入口同步模板优先级；移动任务、换清单清空分组及分组菜单同步模板分组。属性与模板仍在原来的同一笔提交里，撤销与重做同时恢复；日程实例身份和重复范围选择逻辑不在本次改动内。

新增两项案例覆盖看板移列、属性编辑、分组菜单、换清单清空分组，以及一次撤销／重做。比较同一 occurrence key 的未来预览和完成后实际实例，检查优先级、清单及分组一致。

本轮读取 REA 已配置能力：Ghidra 未配置、Hopper 启动器缺失、IDA 连接未配置，当前没有可用的深度引擎。此前追踪该处理器返回 `provider_unavailable`；本轮读取能力信息后继续使用已有静态证据和本地源码，没有将重复的失败追踪当作新结论。

原生工具最初读取到具名临时清单为空，输入受前台状态影响。用户将滴答置前后已成功创建 3 条临时任务、2 个临时标签，分别作为甲标签、乙标签及无标签对照。视图弹层可以打开，但工具点击看板图标落到下方输入框，未完成按标签分组及跨列拖放；随后用户表示这项功能不重要，本轮停止继续核实跨标签看板。不能将这次尝试标为规则验收通过。

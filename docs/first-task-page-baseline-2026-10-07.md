## 测试入口

`macos-native/scripts/run-tests.sh` 现在检查 xcodebuild 本身的退出状态，构建失败立即退出，不继续运行之前的测试产物。XCTest 返回成功但执行零用例时也返回失败。

临时 App 宿主使用 Xcode 的 xctest 可执行文件，并保留构建应用的 Info.plist 声明，以支持通知初始化和应用 URL scheme 验证。默认 JSON 存储通过已有 DEBUG 配置重定向至本次运行的临时目录，运行结束清理；隔离粒度是一次测试运行，显式传入的测试目录仍由用例负责。

验证：脚本回归 4/4；NativeTaskOutlineTests、NavigationPerformanceTests、NativeResourceLinkTests 合计 19/19；实际不存在的测试类执行零用例，入口返回 1。独立进程性能探针 1/1。非空成功、用例失败、构建失败、零用例均有脚本回归覆盖。

## 测量方法与限制

新增 `NavigationPerformanceTests.testFirstTaskPageWithFixedFixtures`。固定 UUID、时间、日历、标题和顺序，分别建立 43 条、200 条收集箱任务；半数包含两行正文。1280×800 测试窗口，先建立空的今天页，再切到收集箱，随后往返两次。断言初始单元格数量小于任务总数，返回时不新建单元格、不重新构建任务投影。

新增 DEBUG 计数：列表容器、单元格、内容配置、协调器更新、reload、行 intrinsicContentSize 查询及行 layout。Release 不包含计时和计数。

这里测的是主线程 CPU 布局调用及短暂 RunLoop 收敛，不是显示器首帧、应用启动或滑动 FPS。reload 是协调器更新时间的子集；行布局与尺寸查询也可能嵌套，不能将列相加。200 条场景在 43 条之后执行，已经享有进程内框架预热，不能据此认定任务更多反而更快。固定英文短标题也不代表复杂真实文档的全部情况。

## 撤回的实验与下一步

试过直接以任务内容初始化 NSHostingView，省去 EmptyView 后再赋值。单次比较约减少 10 毫秒，但运行间差异更大；其他 UI 测试先运行后，原实现也降至约 260 毫秒。因此该产品改动已撤回，不能宣称获得性能收益。

下一步优先拆解行视图首次测量：单独对照标题输入控件、元数据和菜单等子树，固定宽度与内容，寻找能稳定减少重复测量的改动。保留动态行高、行内编辑和拖动语义，验证后才用于产品。

共享任务页容器仍作为后续实验：必须同时处理各 scope 的滚动位置、草稿、焦点和筛选状态。当前 43/200 条首屏固定建立 15 个单元格，说明虚拟化有效；没有证据要求先迁移 SQLite。性能目标暂不设硬阈值，需补充多次独立进程测量和真实首帧记录。

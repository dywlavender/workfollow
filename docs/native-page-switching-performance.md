# 任务、笔记与日历的页面切换

日期：2026-11-01，分支 `experiment/macos-native`。

## 复现与定位

用户反馈已经访问过的页面反复切换也有延迟。本轮测量跨模块切换，区别于任务清单内部切换。

固定资料：80 条虚构待办、12 篇虚构笔记，每篇 80 段正文，1280×800 原生窗口。分别测普通背景、极光主题，以及与日用配置一致的极光加液态玻璃材质。后者关闭背景动画。核心路径为收集箱 → 笔记 → 日历 → 今天，首次进入与再次进入分别记录。另有覆盖四象限、AI 对话、倒数日、摘要、会议、专注的十入口对照。

原生计数确认，再次进入时已有页面宿主和任务行均被复用。导航本身通常不到 0.2 ms，开销主要在页面回到窗口后的视图更新、布局和后续主队列处理。十入口 Debug 对照中，日历回访中位耗时约 114–120 ms，返回今天约 129–133 ms。核心三模块的延迟较低，不能将十入口数据直接当成所有切换路径的统一延迟。

当前安装包是构建 2，包含原生任务行，也带有 Debug 动态库和预览库。项目 Debug 使用 `-Onone`，发布构建使用 `-O`；之前生成的 Release 构建 110 尚未由本次工作替换安装。不能仅根据版本号或“已有原生任务行”就认为当前日用包具有发布构建的性能。

## 已修复的重复通知

1. `NotesWorkspaceView` 离开笔记、关闭 AI 扩展区时，原先会无条件把 `notesAIFrozenWindowWidth` 重新写为 `nil`。这是整个 App 观察的布局状态；即使值没有变化，也会发布通知。现在仅在确实存在冻结宽度时清除，实际 AI 扩展区关闭行为保留。
2. `CalendarSyncCoordinator.refreshAccess()` 原先每次回到日历都会重新发布权限、日历目录和事件列表，值相同也照样通知。App 环境又转发了这些通知，扩大了刷新范围。现在先比较结果，再发布实际变化；仍会重新查询数据，外部修改的日程仍正常更新。事件使用开始时间和 ID 稳定排序。
3. 日历回到同一日期范围、权限也没有变化时，复用当前查询结果，避免重复调用 EventKit。系统日历变更通知仍刷新结果；切换日期范围或权限变化也会触发重新查询。模拟服务回归验证重复回访不增加读取次数，修改系统日程、切换范围、撤销权限后都能正确更新。
4. `WorkspaceSelectionMemory` 回访笔记时，仅在确实有选中项时清除；已经为空时不重复发布。完整外壳回归确认空选中项不通知，真实选中项仍按原导航规则清除。

两项回归先在原代码上失败：普通笔记离开产生 1 次多余布局通知；连续两次刷新相同日历结果产生 6 次多余通知。修正后无变化不通知，真实日程标题变化仍发布更新，已有冻结宽度离开笔记时仍正确清除。

## 方案对照

重复通知修正降低了部分日历回访开销，但没有独自解决全部布局延迟。额外对照也表明：将页面宿主常驻窗口，在当前实现中会扩大隐藏页面的更新与布局，反而拖慢日历和今天；页面尺寸手工布局、单独缓存侧栏也未获得明确收益。上述试验均未纳入正式实现，原有页面保存、清理和焦点交接结构保留。

测试脚本增加 `WORKFOLLOW_TEST_OPTIMIZE=1`，在隔离的测试宿主中开启 `-O`，保留测试所需的动态库和 DEBUG 诊断。该模式用于区分编译优化与业务代码修改的收益，不代表对所有设备的物理点击延迟承诺；正式日用包仍由 `local-app.py build` 的 Release 配置生成。

优化编译通过额外 Swift 编译参数启用，保留独立 XCTest 加载器所需的 Debug 动态库布局。两种编译方式使用同一源码和资料。XCTest 下 `WFMotion` 禁用界面过渡，因此测量的是更新、布局与绘制阶段，未包含用户感知的完整动画完成时间。

## 验证与安装状态

合并后的相关定向回归选择 85 项，84 项通过、1 项因隔离库缺少真实任务而跳过，0 失败。覆盖笔记格式编辑和中文输入法提交、日历任务弹窗与部分行滚动位置、AI 栏窗口扩展与恢复、跨模块状态、任务右键。空选中项修正后，强化后的交互回归与性能用例另行通过。

最终 Release 0.2.0（111）只构建，不执行安装或重启。当前日用 App 保持运行。本轮日用窗口读屏在切换后遇到 ScreenCaptureKit 参数错误，未完成人工验收；进程仍在运行，没有出现本次操作对应的新崩溃报告。不能将打包或隔离测试通过等同于日用卡顿已全部解决。

## 最终性能记录

本轮修复快照在所有构建结束后，串行执行 Debug 与优化编译测试，每种背景 30 轮。每个入口首次访问单独保留，再次访问各有 29 个样本，总计 720 个样本。下面列出极光加液态玻璃场景的中位数及 P95：

| 入口 | Debug 中位数 / P95 | 优化编译中位数 / P95 |
| --- | ---: | ---: |
| 收集箱 | 35.10 / 38.17 ms | 33.61 / 37.96 ms |
| 笔记 | 51.74 / 57.88 ms | 56.28 / 66.22 ms |
| 日历 | 43.19 / 50.85 ms | 49.88 / 66.38 ms |
| 今天 | 83.00 / 89.49 ms | 83.73 / 88.57 ms |

最终对照没有显示编译优化能稳定解决主要延迟；部分优化编译样本反而更慢。此前小样本中约一成的改善不宜作为稳定结论。页面宿主回访的新建数、`rootView` 重设数均为 0，已有缓存生效，剩余成本主要在已有视图的更新与布局。

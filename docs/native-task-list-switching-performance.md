# 清单切换性能修正

本轮补测自建清单与智能清单。上一轮主要覆盖了任务详情切换和“今天／收集箱”，没有把自建清单中的输入框重建、菜单重建和状态恢复完整纳入对照。

清单导航改为只发布实际变化的页面、清单、标签与过滤条件。侧栏清单订阅任务数据和清单状态，不因普通任务选中变化重新计算整组导航。

快速添加输入框现在在 updateNSView 中同步占位文字和字体，不再为更换清单销毁整条输入区。排序和更多菜单也保留控件身份，动作仍按当前清单读取、写入偏好。草稿按清单分别保存，空草稿不存在时不重复删除偏好键。

任务行缓存按任务身份在智能清单间共享；分组标题仍按清单保存。展示内容变化时更新行，普通任务选中由单独的观察器更新，批量选中仍纳入行内容比较。这样既保留行控件，也避免单击标题时重新绑定编辑器。固定行高由原生列表提供，行宿主不再重复请求 SwiftUI 固有尺寸，拖放热区使用同一行高契约。

固定数据包含 60 条虚构任务、3 个自建清单及收集箱，每个清单 15 条，窗口 1280×800。独立复测中，自建清单再次切换的中位耗时：普通背景从约 64 ms 降至 45 ms，极光主题从约 58 ms 降至 42 ms。首次进入自建清单仍需创建行控件，中位耗时约 135–139 ms。首次进入“今天”复用已有任务行后，普通背景从约 177 ms 降至 71 ms，极光主题从约 161 ms 降至 62 ms。以上是 Debug 下更新、布局和绘制阶段的测量；有一次智能清单回访样本约 159 ms，不能据此承诺每次点击都在固定阈值内。原始记录与样本数见 research/task-list-switching-performance-2026-11-01.json。

最终合并源码选中 151 项定向回归，150 项通过、1 项因隔离数据不足跳过，没有失败。包括真实侧栏按钮点击、输入框身份与目标文案、跨清单草稿、中文日期创建落点、菜单作用范围、标题单击编辑、行复用、滚动、多选、右键与背景渲染。

已安装 Release 构建 WorkFollow 0.2.0（109），正常退出旧 App 后备份数据库、模块数据、偏好设置和旧 App。日用窗口已检查工作清单、欢迎看板、今天和收集箱的实际切换与文案；CLI 在首次启动超时后复测成功。编译结束后单独重跑性能用例，避免并行编译的 CPU 竞争影响对照。

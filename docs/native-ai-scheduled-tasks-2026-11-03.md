# AI 定时任务

AI 对话页左栏新增“定时任务”。新建时填写指令、重复方式和执行时间；支持单次、每天、周一至周五、每周。列表可以暂停、编辑、删除、立即执行、停止本轮以及查看最近结果。删除计划保留已经生成的对话和业务记录。

也可以直接对 Pi 说：“每周一上午九点，汇总未完成的待办，列出本周要优先处理的三件事。”App 内 WorkFollow Skill 会将要求保存为 AI 执行计划；普通的任务到点提醒仍沿用待办提醒。当前频率不包含法定节假日判断、自定义 Cron 或每月规则。

## 执行方式

- 按本轮选定的方式，App 运行时到点执行；退出后重新启动、从休眠中唤醒或恢复前台时检查遗漏。同一个计划错过多次，只补最近一轮。
- 每轮读取当前 Pi 文字模型设置，沿用三个对话入口的流式请求、Skill、原生 CLI、长期偏好和操作回执。Pi 管理自己的会话上下文；App 没有新增长短文切分或输入预算规则。
- 任务先记录本轮状态并推进下次时间，再调用模型。执行中退出后，这轮标记为已中断，保留已经完成的操作，不自动重跑。需要重试时可点“立即执行”。单次计划到点触发后自动停用。
- 多个定时任务依次执行。已有主动 AI 请求时等待其完成；新的主动请求优先于后台生成，可能停止正在执行的定时任务。停止状态和结果保留在列表及历史中。
- 每轮执行创建独立对话，结果逐步进入历史列表，不切换当前对话，也不清空未发送的草稿。打开正在执行的结果会连接到同一个实时会话。
- 默认只展示处理结果；指令明确要求记录笔记、创建或修改待办时才调用对应写入功能。结果入口在 AI 对话历史，当前没有额外的系统通知。

## 实现

`AIScheduledJobStore` 原子保存 `modules/ai-scheduled-tasks.json`，包含指令、频率、时区、下次执行时间和最近一轮状态。它与任务提醒、普通待办重复规则分开维护，重启后继续读取本机计划。

`AIScheduledJobRunner` 使用最近执行时刻的一次性主 RunLoop Timer，不做高频轮询。启动、唤醒和时钟变更沿用 App 生命周期通知。模型运行由现有随 App 启动的 AI 后端承接，没有新增系统常驻服务，Node 和 Pi 仍使用本机安装。

CLI 提供 `schedule list/get/add/update/delete/run`。更新或删除使用 `get` 返回的版本；`run` 返回的 `queued=true` 表示已触发，不代表模型已完成。App 自带的 WorkFollow Skill 描述了这些命令以及“执行已有定时指令时不要重复创建计划”的规则。

本轮交互回归还定位到共用 `FirstMouseAction` 的命中范围问题：非活动窗口中的透明控件原来没有判断自身边界，会截走其他控件的点击。现在只响应自身实际可见区域，定时任务的窄窗口入口也支持首击直接打开。

## 验证

验证结果：

- 71 项原生回归通过，包括时间与恢复规则、持久化、CLI、完整聊天窗口中的原生事件交互，以及相关菜单、侧栏、对话、附件和助手记忆。
- 49 项后端回归通过，包括定时请求等待已有主动请求、主动请求优先、简报优先级和计划信息隔离。
- 当前 `ali-Pi/kimi-k3` 在隔离 App 中通过完整真实测试：自然语言创建单次计划，App 到点执行，读取虚构笔记中的“青竹402”，新建正确的结果笔记，并保留原选中对话。核对了单次计划停用、没有新增待办、没有重复结果，以及历史中的实际笔记链接与写入回执。详情见 [虚构资料报告](research/ai-scheduled-tasks-live-2026-11-03.json)。
- WorkFollow Skill 通过结构校验。Release 0.2.0（19）构建和签名验证通过；包内后端、Skill 与源码一致，附带 CLI 帮助包含全部 `schedule` 命令。Node 与 Pi 保持本机外部安装。

共享工作区有其他并行修改，本轮最终原生回归和打包使用固定源码副本；19 个相关功能文件已与主工作区逐字节核对一致。桌面工具的额外人工操作验收遇到超时，没有将它计入通过项。

日用 App 没有在本轮自动替换。

# 打勾 macOS × 滴答清单：控件级对齐方案

日期：2026-09-14  
分支：`feature/flutter-personal-desktop`  
范围：个人版 macOS 任务工作区（侧栏、任务列表、任务详情、弹框与键盘操作）。

## 1. 为什么要改成控件级验收

此前按“页面结构”和“整体风格”验收，无法回答“哪个按钮不一致、弹框哪一项不一致、点击后
状态是否一致”。滴答清单的高级感不只来自颜色，而来自每个操作点的固定位置、明确层级、稳定
反馈和低噪音默认态。本方案把页面拆为最小可验收单元；只有矩阵中的行为和视觉契约都通过，才
能标记该区域完成。

参照边界：以本机滴答清单 macOS 任务工作区为主，用户提供的浅色 Web 截图用于补充字段语义。
两者存在版本差异时，以本机 macOS 的布局和交互为准，不复制团队、同步和云端能力。

## 4. 任务详情最小控件矩阵

### 4.1 顶部操作条

| 控件 ID | 控件 | 默认态 | 操作结果 | 测试定位 |
| --- | --- | --- | --- | --- |
| D-02 | 完成复选框 | 未完成为空心，完成为勾选 | 更新任务状态，列表行同步 | `task-complete` |
| D-03 | 安排日期 | 无日期显示“安排日期”；有日期显示本地日期/时刻 | 打开日期弹框并更新列表分组 | `task-schedule` |
| D-04 | 提醒 | 无提醒仅图标；有提醒显示激活态 | 打开提醒弹框，过去时刻拒绝提交 | `task-reminder` |

| D-07 | 详情关闭/返回 | 固定栏为关闭，窄窗为返回 | 清除选择或回到列表，不丢滚动位置 | `关闭详情` / `返回列表` |

## 6. 交互状态矩阵

| 状态 | 必须验证 |
| --- | --- |
| 默认未选中任务 | 右侧保留干净空态，不显示编辑控件 |
| 选中任务 | 列表行高亮、详情固定出现、标题获得焦点 |
| 悬停任务行 | 只显现行更多按钮，不改变行宽/文本位置 |
| 键盘操作 | `Enter` 打开、`Space` 完成、上下键切换、`Esc` 关闭/返回 |
| 保存中 | 只显示小型状态图标，不能提前显示已保存 |
| 保存失败 | 图标使用错误色，Tooltip 说明原因，正文仍可编辑 |
| 窄窗口 | 列表与详情互斥显示，返回后列表滚动位置保持 |
| 深色模式 | 背景层级、文字、图标、选中态和分隔线均有足够对比 |

## 7. 实施顺序与提交边界

1. **上下文与几何**：第二栏按任务/笔记上下文拆分；固定栏宽度、列表栏宽度、详情栏边界统一。
2. **列表原子控件**：标题工具条、添加行、任务行、悬停按钮、右键菜单逐项统一。
3. **详情原子控件**：顶部五个操作、正文两个编辑器、底部四个操作稳定化并补 key/语义。
4. **弹框原子控件**：日期、提醒、重复、优先级、标签、清单、更多菜单逐项对照。
5. **交互回归**：组件测试覆盖每个入口；Release 构建后按矩阵逐项实机截图验收。

每个阶段单独提交；不把“代码存在”当作“控件通过”。验收记录必须同时写明：自动化结果、
Release 构建结果、原生实机结果和未验证边界。

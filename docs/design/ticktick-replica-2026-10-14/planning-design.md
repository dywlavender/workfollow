## 2. UI 应当形成同一套空间与状态

保留应用现有主框架，重做日历内容区域。上方工具条包含浏览范围、视图切换、前后/今天、添加、安排任务、显示设置。周视图内部依次为日期列头、全天/跨天区、时间轴。左侧时间标尺与列头固定；安排任务面板由工具条展开，位置与开关样式按客户端实际对照校准。

全天区允许拖动底边改变显示高度，空间不足时有明确的剩余项入口。时间轴缩放时以指针或可见中心时刻为锚，不让正在看的任务跳出窗口。近期已有文档提到桌面多日、多周视图，可用同一渲染器的列数/周数扩展；8.0.80 的具体视图菜单须补测后确定。单纯字符串写“6种视图”不足以定义六个入口。

月视图继续使用轻量网格与横向跨天带，但必须由实际月份/浏览窗口决定内容范围，不能继续把今天前后 30 周当作整个可访问日历。当前五行视口可以作为多周滚动模式；标准月模式应完整表达该月所需周行。月模式与多周模式的菜单关系待客户端确认。

日历状态由 CalendarViewport 管理：浏览日期、选中日期、视图模式、可见日期区间、时间轴滚动时刻、缩放级别。月/周/工具条标题都从它派生。翻页后新建默认日期必须在当前浏览窗口内；切换模式保留相同浏览日期。选中任务使用任务/周期身份，不使用颜色、列表位置或日期格下标。

拖动统一分为未拖动、草稿预览、待选重复范围、提交四个可见状态。预览只改本地草稿，不写任务库；时刻标签、目标日期、修改前后的属性在拖动中可见。Esc 取消草稿，鼠标落下才形成一条领域动作。块边缘调整、块整体移动、空白区域选时段使用不同命中区域，不能共享一个“拖 UUID 到日期”通道。

四象限保留 2×2 独立滚动布局、清单分组、完成框及任务详情。象限头部加入编辑规则、排序、布局拖动入口；布局顺序与规则身份分开。任务行显示日期、清单/标签及现有备注、子任务、重复、提醒元信息，列窄时折叠次要元信息，不把全部信息 fixedSize 挤在行尾。

## 3. 操作合同：触发、可见状态、提交、撤销

以下除明确标为官方确认的入口外，预览和撤销组织方式是本项目实现设计，不是已恢复的滴答内部算法。

| 关键操作 | 触发 → 可见状态 | 提交副作用 | 撤销/取消 |
| --- | --- | --- | --- |
| 浏览与切换模式 | 箭头/触控板/模式菜单 → 标题、网格、选中日、新建默认日同步 | 只更新视图偏好和浏览状态 | 不消耗任务撤销；返回今天始终定位实际今天 |
| 月格或全天区创建 | 单击空白（官方桌面入口）→ 就地标题编辑，明确显示预置日期和全天状态 | 回车/保存时创建一个 Task，保留用户选择的清单/标签/优先级 | 一次撤销删除整条新任务；Esc 不创建 |
| 时间轴创建时间点 | 单击目标时刻 → 草稿显示开始时刻、无结束时间 | 新 Task：dueAt 为该时刻、hasTime=true、dueEndAt=nil | 一次撤销创建；关闭草稿不写入 |
| 空白拖选时间段 | 按住并拖动（官方入口）→ 区间背景与起止时刻，松开打开草稿 | 创建时一次写起止时间；起点终点统一校验 | 一次撤销整条任务；拖动期间 Esc 无写入 |
| 月格拖选多日 | 从起始格拖到结束格 → 连续日期选择与全天区间摘要 | 创建全天范围；现有 dueEndAt 的末日含义保留 | 一次撤销创建 |
| 时间块整体移动 | 拖块正文 → 目标日期/时刻幽灵块，跨天带保留鼠标在原区间中的偏移 | 平移开始与结束，保持真实时长；清单、优先级、独立 deadlineAt 不随之变化；提醒策略见下文 | 一次恢复安排与本次随动提醒；同位置落下不增加撤销步骤 |
| 调整区间边缘 | 鼠标悬停边缘（官方有上下箭头）→ 调整游标、起止时刻和时长预览 | 只改所拖边缘；点任务首次拉边缘才产生结束时间 | 一次恢复完整原区间；Esc 回原位 |
| 全天与时间轴转换 | 全天块拖到时刻（官方确认）→ 日期+时刻草稿；反向转换为项目设计待测 | 有结束区间时保留可解释的长度；去掉时刻时保留日期覆盖，提交摘要说明变全天 | 一次恢复原安排；反向规则先补测再固定 |
| 未安排任务入日历 | 从安排面板拖到日期/全天区/时间轴 → 目标高亮、日期或时刻预览 | 日期格/全天区写全天安排；时间轴写时间点。原截止、组织归属、重复规则保留 | 一次撤销后任务回安排池，提醒随域规则恢复 |
| 取消安排 | 任务菜单清除安排 → 清楚显示变为无安排日 | 清 dueAt/hasTime/dueEndAt；独立截止与重复的具体保留策略沿用明确菜单语义 | 一次恢复；“清除所有日期属性”与“只取消安排”不混成同一动作 |
| 月格 +N | 点击 → 当天完整任务浮层，可完成/打开/拖动 | 仅具体完成/编辑动作写任务 | 打开浮层不消耗撤销；完成一次可恢复 |
| 完成/恢复 | 点完成框 → 月/周/安排区/象限同步；重复任务显示新周期 | 统一调用完成领域动作，重复推进由同一引擎处理 | 一次恢复完成状态、周期推进与相关例外；不遗留重复可见实例 |
| 未来周期改期 | 拖动虚拟周期 → 日期草稿；松开出现周期范围选择 | “仅此周期”写该周期覆盖；其他范围修改系列，详见第 5 节 | 取消选择不写库；一次撤销覆盖或系列分段 |
| 象限内排序 | 手动排序下拖行 → 插入位置线；自动排序下行不暗示可手排 | 只改该象限手动序列，不改日期/优先级 | 一次恢复行序；同象限普通 drop 不改属性 |
| 象限间移动 | 拖入另一象限 → 规则命中预览、将改哪些日期/优先级 | 先求满足目标规则的最少改动，再一次提交属性；不能先改优先级再独立改日期 | 一次恢复所有属性与行序；无法满足的目标给原因并不提交 |
| 象限规则编辑 | 编辑面板 → 名称、条件、各象限数量与重叠命中预览 | 保存配置；重新投影，不批量改任务属性 | 配置撤销恢复上套规则，任务内容没有被改动 |
| 象限换位置 | 拖象限标题 → 布局占位 | 仅更新 displayOrder；不改变象限规则或归属优先顺序 | 一次恢复布局；任务优先级/日期保持 |
| 象限内创建 | 加号 → 可见的默认日期/优先级/清单/标签与目标象限摘要 | 按草稿一次创建；用户修改条件后预览实际归属，不能秘密塞 fallback 日期 | 一次撤销创建 |

时间步进、边缘命中范围、按住多久才触发拖选与分页触发范围属于待测参数，不在本轮写成滴答数值。手势解释只用于实现可观察的入口，不复制未核验的阈值。

提醒：相对 reminderOffsets 保持偏移并随新安排计算。旧 reminderAt 没有锚定类型，不能仅凭它落在某一天就判为绝对或相对。新增 ReminderSpec 区分相对安排与固定时间；旧数据先保留 absolute 语义，新面板明确选择相对提醒时写 relative。对旧单点提醒是否随拖动改期，要用现有导入样本和真实客户端补测，再制定一次性兼容规则；不把所有提醒一刀切平移。

## 4. 模型、投影、动作与组件

### 4.1 最小新增模型

| 模型 | 核心内容 | 为什么必须有 |
| --- | --- | --- |
| CalendarViewport | browseDate、selectedDate、mode、visibleRange、scrollMinute、scale | 消除翻月/加号/切周不同日期的现有问题 |
| CalendarPreferences | 完成、未来周期、子任务/检查项、专注层开关；清单/标签显示范围；着色方式；周首日；全天区高度 | 每个视图共用一套可见性和显示配置 |
| CalendarOccurrence | 稳定 occurrenceKey、真实 taskID 或 seriesID、有效安排、显示属性、真实/虚拟类型 | 渲染未来周期而不预写一堆真实 Task |
| CalendarPlacement | 全天单日、跨天带、单日时间点、单日时间段；日期分段与重叠道 | 各视图只画投影结果，不各自猜任务该放哪里 |
| TaskDragPayload / CalendarGestureDraft | 任务或周期目标、操作类型、原安排、抓取偏移、候选安排 | 现有 String UUID 不能表示虚拟周期、边缘调整或跨天抓取位置 |
| TaskSeries / OccurrenceKey / OccurrenceOverride | 重复规则、起算模式、时区与锚；原始周期身份；单周期改期/跳过/完成覆盖 | 单周期变动不能污染整个系列，改期后周期身份不能跟着改 |
| MatrixConfiguration | 稳定象限 ID、名称/图标/颜色、规则、displayOrder、匹配策略、分组/排序与创建默认值 | 象限的位置不能再等于枚举下标或固定标题 |
| MatrixRule / DatePredicate | 清单/标签条件、允许优先级、日期依据、相对/绝对范围、是否含无日期或过期 | 不复用 SavedFilter.today 的“含过期+截止”快捷语义冒充象限时间范围 |
| MatrixDropProposal | 原目标、拟变字段、满足情况、需要选择的组织属性、最终归属、操作摘要 | 自定义规则必须可解释地反求属性修改 |
| WorkspaceMutation | tasks、series、overrides、任务顺序及必要配置的同一原子修改 | 现有 WorkspaceStore 撤销只覆盖任务/清单，新增系列与例外必须一起进退 |

列表、标签的引用应复用待办模块的稳定标识方案。若这一阶段仍以名称存储，改名命令必须同时维护日历范围、象限条件和保存过滤器，不能让这些配置留着旧字符串失效。

### 4.2 日历投影管线

从任务集合与系列中按可见窗口生成 occurrence；应用删除、放弃、跳过、完成和显示范围过滤；应用周期覆盖并以 occurrenceKey 合并真实与虚拟项；将任务分为全天、跨天、时间点和时间段；对时间轴中的相交区间分道；最后产生渲染所需的块、溢出计数和当天完整列表。

时间轴区间使用半开区间做重叠布局，终点恰等于另一任务起点不挤成一组。一个重叠组按开始时刻分配可复用列，宽度依据该组同时重叠数，不随列表创建顺序改变。时间点允许有最小可见高度，但这个高度不自动落库为任务时长。

跨天任务按官方分区先进入全天/跨天区，显示首尾日期和必要的时刻信息；精确样式待本机校准。不要为了在后续日期可见而复制真实 Task。月格、+N 浮层、周上栏必须读取同一批 occurrence，避免同一任务一处有、一处没有。

全天区与月网格按可用空间裁剪、计算隐藏数；先过滤已完成，再分配跨天 lane。现有“先给所有色带排 lane，后过滤完成”的做法会留下空槽；跨天色带也不能无上限绘制到下一周行。

缓存键至少包含任务修订、系列/例外修订、配置修订、可见日期窗口与日期刷新。横向翻页扩展附近窗口，缩放只重算坐标，当前时间指示线只刷新自身；不重新对几百天逐日全量筛任务。显示范围改变时，安排池和日历同时刷新。

### 4.3 动作收口

在 TaskActions 层新增统一 scheduleMutation 与 recurrenceMutation，TaskWorkspaceModel 仅转发。已有 SchedulePlan / ScheduleTarget 可继续作为日期面板与批量提交的公共载荷；手势新增操作类型与周期范围，不再分别调用 setPriority、setSchedule 形成多次提交。

WorkspaceStore.transaction 扩展为覆盖任务、系列与周期例外的聚合提交。一个动作只发布一个完整变化集、增加一次撤销记录；领域完成后，日历、四象限、待办、提醒和持久化都消费同一结果。拖动途中不发送业务变化事件。

UI 组件边界建议为 CalendarToolbar、CalendarAllDayArea、CalendarTimeline、CalendarArrangePane、CalendarDayAgenda、CalendarDisplayOptions、CalendarInteractionController；四象限增加 MatrixRuleEditor、MatrixSortMenu、MatrixLayoutController。保留现有 TaskQuickComposer 与 TaskInspectorShell 作为内容编辑面，修改草稿默认值和宿主，避免再做一套日期编辑规则。

## 5. 重复虚拟周期与单周期修改

OccurrenceKey 用系列 ID 与未改期前的计划周期标识组成。比如每周五系列的 10 月 16 日这一期改到 17 日，身份仍然是“原 16 日这一期”，否则原位置会再次被重复引擎生成。

真实 Task 保留现有 UUID，历史完成记录继续是实际记录；未来周期只由投影生成。TaskSeries 保存稳定规则和模板属性，OccurrenceOverride 记录某一期的安排或状态变动。渲染先用覆盖替换基准周期，再与已实现的 Task 合并，不能同时画“虚拟原日期”和“真实改期日期”。

| 范围 | 本项目写入方案 | 撤销 |
| --- | --- | --- |
| 仅此周期 | 在原 occurrenceKey 上写安排覆盖；改变日期不改变系列锚点和后续周期 | 删除/恢复本次覆盖及其实现记录，一次操作 |
| 此周期及后续 | 以原周期边界切分系列，旧段保留之前周期，新段承接剩余次数、终止边界和新的模板/规则 | 系列分段、相关覆盖与任务引用一并恢复 |
| 所有未完成周期 | 修改系列未完成部分所选字段；完成历史保留；已有单周期覆盖的处理在真实客户端校准后固定 | 模板、未完成实例与受影响覆盖一并恢复 |

上表是可实现的数据策略，不是由 nib 控件名称推导的滴答内部实现。单周期例外是否包含优先级、清单、标题等字段，以及“所有未完成”是否重置已有例外，需要下轮补测；先让载荷表示显式 changedFields，避免写整个任务覆盖不相关属性。

到期起算系列的未来日期可明确生成。完成日起算的未来周期受尚未发生的完成时间影响，不应把推算值显示成确定安排；当前周期照常显示，后续是否展示预计周期及其样式待客户端验证。引擎仍共享同一规则来源，不另写一个仅供日历的重复推进算法。

完成、跳过、仅此周期改期都经过同一系列动作。区间长度、组织分组 sectionID、清单/标签、提醒偏移与附件引用统一继承。不能重复使用当前 makeNextOccurrence 里未带 sectionID 的字段复制，也不能完成后再次生成已经由覆盖实现的同一期。

## 6. 象限配置与拖动求解

### 6.1 配置形状

内置三个可解释预设：优先级映射、时间+优先级、旧版原生三天规则。前两个对应滴答公开能力，确切默认优先级映射和日期边界先客户端校准；第三个专为现有项目数据兼容，明确命名，不能包装成滴答默认。

每个象限配置稳定 ID、名称、图标/颜色、规则、分组方式、排序、创建默认值。displayOrder 单独保存。规则可选清单/标签、优先级集合、日期依据与范围、含无日期/过期。日期依据默认使用安排日；支持独立 deadlineAt 属于项目扩展，入口明确写“按截止日期判断”，不偷偷改变旧规则。

规则求值先返回所有匹配象限和未匹配状态。规则重叠时的滴答实际行为尚未验证。建议实现可切换的匹配策略，V1 暂定独占归属，使用独立 conflictPrecedence；配置预览显示重复命中及其最终归属。象限换位置不会改 conflictPrecedence。若客户端确认同任务可在多处显示，只切换策略，任务数据和拖动求解器无需重写。

未命中不是默认塞进 IV。规则编辑预览可查看未命中的任务数；回到任务页仍可找到这些任务。这个结果使“只看工作、未来7天”等范围真正生效。

### 6.2 求解原则

跨象限拖动先生成 MatrixDropProposal，求候选字段后再次运行规则。只有候选真正满足目标才可提交。正常情况优先保留已有日期、时刻、范围、优先级、组织归属；目标条件已经满足的字段没有修改理由。

| 目标规则 | 候选方案 | 可见反馈 |
| --- | --- | --- |
| 纯优先级映射 | 只改目标所需优先级；日期保持 | 预览“优先级改为…” |
| 优先级+日期范围 | 优先级在允许集合内就保持；原安排日在目标范围内就保持；否则选范围内接近原安排日的日期，保留时刻/区间 | 显示日期和优先级实际改动，不能所有 I 都强制今天、所有 II/IV 都强制下周 |
| 目标要求无日期 | 清安排日、时刻和区间；独立截止由日期依据决定是否保持 | 显示“取消安排”，不使用隐藏的 +7 天替代 |
| 目标要求特定清单/标签 | 当前已满足则保持；不满足时提出具体组织属性变更，多个可选清单/标签让用户选择 | 轻量选择面显示实际将移动的清单/添加移除的标签，确认后同事务提交；不静默移动到任意清单 |
| 候选会仍归属于其他象限或目标条件不可满足 | 显示冲突条件，提供修正候选/编辑规则入口 | 无符合候选时不写任务，不把任务强行丢进界面后立即弹回 |

同象限拖动只允许手动行序，不触发日期或优先级变化。非手动排序不暴露伪插入线。跨象限成功时，属性和手动行序是一个事务；任务日期/优先级各改一次造成两个撤销记录的现状必须消除。

新建任务的预置值由当前象限规则生成，并直接显示在草稿上。用户修改后不再符合该象限，草稿预览实际去向；回车尊重草稿，不靠不可见 fallback 强迫任务留在原象限。

## 7. 迁移兼容

1. Task.id、原有 dueAt/hasTime/dueEndAt/deadlineAt 与完成记录保持。全天范围的旧 dueEndAt 表示包含末日，投影可转换为内部排版边界，不能批量把旧日期加一天再落库。
2. 新增系列/周期引用使用可选解码。已有活动重复 Task 先获得独立系列身份；缺失链路的旧完成任务仍保留独立历史，不按同名标题猜测属于同一系列。首次打开日历生成未来投影不落真实 Task。
3. 旧重复类型、remainingCount、终止日和农历字段保持原含义。引入系列后只有明确的编辑/完成命令推进计数；导入和浏览不消耗重复次数。
4. 原生现有象限用户使用“旧版三天规则”初始化，升级不会无说明把任务全重新分配；用户切换到滴答式预设后保存选择。新安装采用经客户端校准后的预设。
5. 原有按任务着色继续可选；加入按清单/优先级/标签着色。完成开关、周首日、显示范围、全天区高度统一持久化，切页不丢。
6. 新持久化结构包含 series/overrides 与配置，导出、导入、撤销同步支持。初次升级只添加缺失结构，重复打开不重复创建系列。现有任务、附件及历史无需整体搬迁。
7. 清单/标签改名沿同一业务动作更新规则与显示范围引用，防止当前字符串过滤器改名后失效的问题进入新配置体系。

## 9. 实施顺序与 REA 补测

第一批修当前可见性、日期锚点、+N 和象限事务，同时建立统一投影/动作合同。第二批实现周时间轴、全天区、安排池、拖动和边缘调整。第三批实现系列/例外与未来周期、单周期编辑，并与待办重复模块一起验收。第四批完成象限规则、排序与组织属性拖动求解。颜色、像素几何和动画跟随这些稳定行为逐项校准，不能用外观验收替代数据与撤销验收。

下轮在可使用真实日历功能的客户端采集场景，会员演示只用于布局参考，不能代替读写验证：

- 周时间轴、全天区、安排面板、任务详情、重复范围弹窗、规则编辑器及其 hover/选中/拖动状态截图与可访问性结构。
- 同一普通任务：时间点、时间段、全天、跨天四种安排，观察分区、标签、选择和详情打开位置。
- 拖动正文与上下边缘，观察日期/时刻吸附、抓取偏移、默认完成框可见性及取消行为。
- 无日期任务入全天与时间轴、重新取消安排，观察提醒、重复与独立组织属性的变化。
- 重复任务仅此周期、此周期及后续、所有未完成三个范围，观察当前/未来/历史与已有例外。
- 两种内置象限预设的精确条件，重叠规则、未命中规则、清单/标签范围冲突与同象限排序。
- 任务同象限/跨象限拖动后具体优先级与日期，客户端撤销恢复哪些字段。
- 实测界面尺寸、字体、颜色、间距、缩放和手势参数后填写 token；全部数字附具体场景和对应客户端版本。

补测结果只替换对应合同与 token，不推翻 Task、周期身份、投影和事务的分层。这样可以先搭正确的数据与交互骨架，再把未确认的滴答细节精确补上。

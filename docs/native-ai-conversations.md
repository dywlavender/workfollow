# 三种 AI 对话入口

## 交互

- **选区浮窗**：笔记正文选中文字后，在原有浮动工具条点击“AI 润色”，打开可拖动、缩放的浮窗。支持继续输入修改要求、自由讨论、查询或保存 App 内容、流式回复及停止。完成后选择替换原选区、在选区后插入或复制。替换与插入沿用编辑器撤销；切换笔记或修改原文后不会写到旧位置。
- **独立对话页**：左侧功能栏“AI 对话”，与任务、笔记同级，也可以通过快速打开搜索“AI 对话”。左侧历史栏顶部放“新对话”，底部放“模型设置”，中间为会话历史；窄窗口通过带文字的“历史对话”按钮打开同一栏。支持连续聊天、停止，记录本地保存。
- **笔记侧栏**：可以直接自由聊天；整理、润色和提取待办是附带当前内容的一键提问，下一轮不自动重做上一动作。待办候选和文稿仍可编辑、创建、替换或另存。主窗口和同篇笔记浮窗共用该笔记的会话。

输入框 Return 发送、Shift-Return 换行；中文输入法确认候选时不发送。快捷提问先给可采用结果，不自动创建或覆盖。三个入口在收到用户明确的新建、保存或修改要求后，均可通过 CLI 执行并显示实际操作回执。

三个入口均支持通过回形针选择图片或文件、粘贴图片、拖入文件。复制图片或截屏后，点击输入框按 `⌘V`，即可看到附件预览；也可以在 Finder 复制图片文件后粘贴。发送前可预览和移除，也可以只发附件；发出后附件留在对应消息中，可点击打开。笔记侧栏无需先选择操作即可发送消息；Pi 保留会话中的附件历史，重试重新携带原附件。图片直接以 Pi RPC 的 `images` 内容块发送，沿用当前所选模型，不查询图片能力、不自动切换模型。PDF、Word、RTF 和文本文件优先由原生层提取文字；三个入口都可使用 Pi 的工具和本机 Skill 读取附件路径。

历史行在选中或悬停时显示删除按钮，也可以右键选择“删除对话”。确认后删除本地显示记录及对应 Pi 会话；正在进行的回复先取消并等待退出，避免会话文件重新写回。删除当前记录后切换到最近更新的剩余记录，全部删除后回到空白新对话。已创建的待办和笔记保留。

## 共用部分

三个入口共用完整的 `AIConversationComposer` 输入区：附件条、选择文件、图片粘贴、拖入文件、中文输入占位、回车发送、发送/停止按钮均在一处维护。通过 `AIConversationComposing` 读取当前模型状态，避免快速输入后回车时使用上一帧的发送条件；生成过程中按回车保留待发送草稿，由停止按钮取消当前请求。侧栏只采用紧凑尺寸。

三个入口共用 `AIConversationModel`、`AIConversationView`、`AIConversationClient` 和 `conversation.send`，统一消息、流式、停止、重试、Skill 和操作回执。`NoteAIConversationModel` 只附上当前笔记并投影可采用结果，不再持有独立生成任务，也不再调用 `text.tasks` 或 `note.rewrite`。各入口保留自己的会话身份与来源范围。

`conversation.send` 发送当前消息及可选的当轮 `preset`、`source`。快捷要求只拼进当前用户消息；常规消息没有 preset，不继承上一动作。选区首次携带选中文字，笔记快捷提问携带点击时的内容快照；普通笔记聊天引用当前笔记 ID，由 Pi 按需读取最新内容。Pi 通过 `--session` 恢复自己的会话文件，管理历史、压缩和内部重试，应用不重建压缩后的上下文、不做长短文分段，也不设置额外输入预算。每轮结束或取消后关闭本轮 Pi 子进程，下轮恢复同一文件。

独立页、选区和笔记分别使用 `chat`、`selection`、`note` 场景及独立会话文件。选区入口只带选中文字，不自动携带整篇笔记。独立聊天按用户问题通过 Skill 按需查询和操作 App 内容，不预先灌入整个笔记库。

## 共用的 App 能力

复用仓库 `.agents/skills/workfollow-cli/SKILL.md`，随 App 打包到 `Contents/Resources/Skills/workfollow-cli/SKILL.md`，通过 Pi 的显式 `--skill` 参数加载。无需安装到用户的 Pi 全局目录，也不修改 Pi 模型配置。

三个入口同时启用 Pi 的 Skill 自动发现，沿用本机 Pi 的全局 Skill 目录和配置；内置 WorkFollow Skill 通过显式参数附加，可以和其他 Skill 共存。设置、模型配置和外部 Pi 会话不作修改。

## 日常业务操作

独立聊天的“引用资料”可以选择当前或其他笔记、待办；请求带记录类型及 ID，由 Pi 按需读取最新正文。历史保存引用选择。会议通过 `meeting list/get` 查询，跨资料使用 `knowledge search`；会议发言链接保留 `?line=`，打开后定位原发言。准确任务统计使用 `task count`，日期范围使用 `--from/--to`，不把检索片段数量当成总数。

CLI 支持绝对提醒、相对提醒及重复规则；安排日期和提醒分开保存。原生 App 在写入并保存成功后，根据实际数据生成回执，显示日期、提醒、重复、清单与重要性，提供打开和撤销。回执直接来自业务接口，不从模型的回复文字推测是否执行成功。撤销沿用原生事务栈，只能倒序撤销当前可撤销操作；重启后的回执仍保留，撤销能力随原生撤销栈恢复为不可用。

对话支持复制、指定失败回合重试、最后一条停止回复的继续，以及标题、列表、表格和代码块。较早失败回合的重试绑定原问题；已成功的操作作为上下文告知 Pi，不重复创建。读取资料或 Skill 与执行操作分别显示对应状态。

历史栏底部显示实际 Pi 模型，可直接切换。设置在选择直接调用时仍保留独立的 Pi 对话模型入口；“检查本机 AI 配置”检查 Node、Pi、可用模型列表和 Skill 注册，不发送模型提示词，也不代替云服务生成质量测试。

会议录音菜单支持回放和重新转写，发言时间可定位录音；对话行右键可校正文字和讲话人，并选择是否修改同一讲话人的其他片段。原有片段作用域在未改名时保留。重新转写成功后才替换对话，支持恢复上一版；校正后旧纪要保留，待重新编写。流式语音模型按音频时长回放输入，HTTP 语音模型使用较长音频段重新识别。

三个入口均启用 Pi 内置 `read` 和 `bash`，提供 `WORKFOLLOW_CLI`、`WORKFOLLOW_APP` 环境变量，指向当前应用的原生 CLI 和 App。CLI 路径还加入该 Pi 子进程的 PATH 首位，移动 App 或安装到另一台 Mac 时仍定位当前实例。会议纪要等非对话任务保持原来的工具策略。

Skill 约定先搜索元数据、按需读取正文，修改前获取最新版本；通过 CLI 保存并核对成功，不直接操作数据库。查询和分析请求只读；用户明确要求记录或调整时执行写入。回复使用简洁说明及可点击的 `workfollow://` 链接，内部版本号和命令不进入普通回复。

三个对话入口统一使用本机 Pi 和同一个 Pi 对话模型配置。其他非对话 AI 任务仍保留既有直接调用适配器。

## 本地数据

独立页显示记录位于工作区 `modules/ai-chat.json`；Pi 会话位于 `modules/ai-conversations/{chat,selection,note}/`。独立聊天的历史和当前选择在重启后恢复。选区与笔记侧栏在本次编辑会话中各自连续对话。

导入的附件副本保存在 `modules/ai-conversations/attachments/{场景}/{会话ID}/`，显示记录只存文件信息，不内嵌图片数据。独立聊天重启后恢复附件，失败回合重试保留原附件；删除对话时清理该对话的附件副本。移除待发送附件不会影响历史消息中的文件。笔记侧栏的图片和文本现在也由统一的 Pi 会话处理。

真实模型复测仅使用虚构代号：第一次回复“已记住”，第二次恢复同一 Pi 会话后正确回复“海蓝752”，两轮分别约 5.19 秒和 1.01 秒。没有发送用户原有笔记、任务或录音。

## 快捷提问与可采用结果

快捷要求集中在后端 `PRESETS`，以普通用户提问进入同一个 Pi 会话。全局提示词允许开放聊天，候选调整可返回新一轮结果；普通讨论不要求固定输出格式。

可采用结果使用可选的 `workfollow-tasks` / `workfollow-note` 结果块，前端只在出现这些结果时生成候选卡片或文稿。机器载荷在流式显示时隐藏。旧服务对明确快捷请求返回的纯 JSON 或正文仍可采用，普通聊天不会触发这条兼容解析。显式提取保留原文依据校验，开放式建议允许没有原文摘录。解析结果本身不写业务数据；创建、替换、另存和撤销仍由原生业务接口完成。卡片创建、另存或替换后的实际结果链接会带入后续提问，Pi 能区分候选与已经保存的记录；CLI 操作回执同样进入会话状态。

2026-10-30 回归：会话、结果、回执、采用操作与输入交互的 30 项原生回归，以及 12 项后端测试通过。当前 Pi 模型用固定虚构资料连续执行提取、普通讨论、修改候选日期，分别约 3.9 秒、7.5 秒、2.6 秒；同一会话续接，未访问真实笔记或待办。

# 任务行按需呈现与测量对照（2026-10-07）

## 保留的改动

1. `TaskTreeRenderContract` 的几何采样改为 DEBUG 环境显式启用。几何、完成行、点击归属及任务切换渲染测试启用 `recordsTaskTreeFrames`；普通 Debug 页面不再为每行的标题、勾选框、预览等元素添加测试 GeometryReader。Release 原本没有这些采样，本项仅影响 Debug。
2. `SchedulePopoverPresentation` 只在打开时建立 GeometryReader 和日期面板锚点。窗口归属读取器继续保留，日期按钮和右键显式位置的定位契约不变。
3. `AnchoredPropertyPanel` 关闭时不调用内容构造闭包，清空保留的内容。打开/更新时仍使用当前内容及环境；面板关闭、窗口关系和焦点策略继续由原协调器处理。
4. 删除任务行中没有任何入口会置为 true 的 `showTagPicker` 及其锚点。实际右键标签选择器保留，源代码契约改为检查实际入口。
5. 分组“移动到”使用同一共享面板，宽度仍为 230，使用支持搜索框的 panel 焦点策略；保留非空 section 判断，未分组静息态保持关闭。

## 实验与结论边界

使用前一份基线的固定 43/200 条任务、时间、UUID 和 1280×800 窗口。独立测试进程，每个进程先建立今天页再首次进入收集箱；测量 CPU 布局调用，未测显示器首帧或刷新率。

标题输入框的实验：直接响应有限宽度提议并返回固定 18 高度。改动前三轮 43 条首次布局为 278.71、278.73、277.50 毫秒；改动后三轮为 279.66、276.63、280.10 毫秒。尺寸查询均为 153 次，没有稳定收益，已撤回该实验。

元数据、标题编辑器和单行预览保持原实现。本轮没有证明它们的单独贡献，也没有验证共享任务页容器的收益。后续应进一步测量实际首帧，并对行视图各部分做控制变量实验；当前数据不能归因于存储或屏幕刷新次数。

早期机器负载波动使原实现的一次测量达到 635 毫秒，不作为稳定性能收益基线。最终对照另作独立运行记录。

## 最终旧实现/优化实现三轮独立进程对照

恢复旧任务行、共享面板和日程修饰符，同时启用原先始终运行的 DEBUG 几何采样，完成三轮；自动恢复当前优化源文件后，再完成三轮。两组使用相同的 DEBUG 测量接口、Xcode 构建配置、固定数据和窗口尺寸。测量按组顺序执行，不是随机交替。

表内均为三轮中位数，单位毫秒。

| 任务数 | 旧实现首次布局 | 优化首次布局 | 旧实现总时间 | 优化总时间 |

| 43 | 338.77 | 270.54 | 355.45 | 292.93 |

43 条首次布局下降约 20%，总时间下降约 18%。行 layout 累计从 144.40 降至 89.39 毫秒；尺寸查询累计从 110.47 降至 106.48 毫秒。尺寸查询次数从 153 变成 168，没有减少，因此不能宣称已解决重复尺寸查询。布局与尺寸计时不能相加。

这些结果证明本轮组合改动在此 DEBUG 场景下减少了主线程布局成本；没有把三项改动各自的收益分离，也没有证明 Release 能获得相同比例的收益。首次成本仍明显高于返回页面，尚未达到更低的首帧目标。

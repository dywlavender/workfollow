# 应用图标（2026-10-06）

## 起因

这个 app 之前**没有任何图标**：没有 `Assets.xcassets`，没有 `AppIcon`，`WorkFollow-Info.plist`
里没有图标键，`project.pbxproj` 里也没有 `ASSETCATALOG_COMPILER_APPICON_NAME`。
所以它在 Dock / Finder / ⌘Tab 里显示的是系统给无图标应用的通用占位图。

## 设计

**浅色纸面底 + 靛蓝对勾 + 琥珀清单条。**

| 元素 | 值 | 来源 |
| --- | --- | --- |
| 纸面底 | 白 → `#EDEDED` 垂直微渐变 + 7% 黑描边 + 顶部白色棱光 | 见下「为什么不是彩色方砖」 |
| 对勾 | 靛蓝 `#7B80F4`，墨迹宽 = 方砖 46%，笔画 78（方砖单位） | 控制点取自 Web 端 favicon；色值见下「蓝度」 |
| 琥珀条 | `#F2A732`，宽 = 方砖 40%、高 54、两端全圆角，与勾间距 46 | 设计 token 里的暖色档（`WFColors.warning` 那一族） |

### 蓝度：为什么是 `#7B80F4`

第一版用的是 `#4F51E5`（favicon 渐变的深端），用户反馈「太深了」。拉了六档比过：

| 色值 | 白底对比度 | 判断 |
| --- | --- | --- |
| `#4F51E5` | 5.8:1 | 原值，太重 |
| `#5B5CEB` | 5.2:1 | = app accent，还是偏深 |
| `#6B70EF` | 4.1:1 | 可用 |
| **`#7B80F4`** | **3.4:1** | **定稿**：明显变淡，16pt 下勾形仍立得住 |
| `#8B90F8` | 2.8:1 | 16pt 开始发虚 |
| `#9B9FFC` | 2.3:1 | 太淡 |

`#7B80F4` 落在 favicon 渐变（`#818CF8` → `#4F46E5`）的**浅端**，所以仍在品牌色域内，
不是随手调亮。前后对照见 `screenshots/app-icon-2026-10-06/07-blue-lighter.png`。

### 对勾的几何来源

仍是产品自己的记号：`workfollow-flutter-personal/frontend/public/favicon.svg` 里的
`M17.5 33.5 L27.5 43.5 L46.5 21.5`（stroke 7，64pt 框）。**只借形状，不借配色和构图**——
见下。

### 为什么不是「彩色方砖 + 白勾」

第一版做的是饱和靛蓝方砖 + 白勾。用户反馈「很丑」，量下来三条硬伤：

1. **对勾偏右下各 100px（占方砖 12%）**——真 bug。勾的坐标按 1024 画布算的（已含 100pt
   边距），却画进了 824 的方砖坐标系，于是又叠了一次偏移。实测勾墨迹中心 `x=611.5 / y=618.0`，
   方砖中心 `511.5 / 521.5`。
2. 方砖明度极差 **109**，左上角 `rgb(134,144,248)` 洗白——就是「网页渐变」味的来源。
3. 勾墨迹占方砖宽 **54%**，偏大偏粗。

更根本的是方向错了。**把参照物（滴答清单 macOS 版）的 `AppIcon.icns` 拆开量**才发现：
它的图标是**浅色纸面底 + 蓝色圆环 + 琥珀色勾**，靠两种颜色的笔画立身份，
**不是**「彩色方砖 + 白勾」（那是它的手机版 / 网页版）。

而我们 app 的界面本身就是浅色 + 靛蓝强调色，所以浅底才是一致的；做一个饱和靛蓝方块，
既不像自家 UI，又是待办类 app 里最俗的那一种。

### 试过但淘汰的方向

| 方向 | 为什么不要 |
| --- | --- |
| 深靛蓝底 + 发光勾 | 太暗，勾的对比不足，32px 下糊成一团 |
| 层叠方砖（三张错位卡片） | 32px 下错位糊成一片 |
| 浅底 + 靛蓝环 + 琥珀勾 | 太像参照物本身 |
| 靛蓝方砖 + 日历头带 + 白勾 | 能用，但不如浅底那版和 app 界面一致 |

四个方向的对照见 `screenshots/app-icon-2026-10-06/05-redesign-options.png`。

## 几何：走 Apple 自己的图标网格

- 画布 1024pt，圆角方砖 **824×824 居中**，四边各留 100pt。
- 圆角半径 **185.4**，且必须用 `.continuous`（squircle）——用正圆弧画出来四角会明显「胖」。

### 三条踩过的几何规矩

1. **画进方砖的路径必须用「方砖本地坐标 0..824」**，最后再整体居中到 1024 画布。
   用画布坐标直接画进方砖会多叠一次 100pt 偏移（就是上面第 1 条硬伤）。
2. **对勾按墨迹包围盒居中，不是按三个控制点居中**——两者中心不一样。
3. **方砖的 ZStack 必须显式 `.frame(width: tile, height: tile)`**。少了它，里面的
   `RoundedRectangle` / `Path` 这些 flexible 的 shape 会撑满整块 1024 画布，
   于是既没有 Apple 的 100pt 边距、记号也跟着偏 100px。
   ⚠️ 这个坑我在调参脚本里**又犯了一次**：第一版对照表上你看到的四个候选全是「满画布 + 偏移」的
   错误渲染。修正后重新出了一版对照表，方向没变，但边距和居中都是对的。

## 落点

```
macos-native/WorkFollow/Resources/Assets.xcassets/AppIcon.appiconset/   ← 十个 PNG + Contents.json
macos-native/scripts/make-app-icon.swift                                ← 图标的唯一来源
macos-native/WorkFollow.xcodeproj/project.pbxproj                       ← ASSETCATALOG_COMPILER_APPICON_NAME = AppIcon（Debug/Release 各一处）
```

工程用 `PBXFileSystemSynchronizedRootGroup`，所以新增的 `Resources/` 目录**自动**进了
Resources 构建阶段，不需要额外加文件引用。

**图标不是手绘位图，是渲染出来的。** 改图标请改 `scripts/make-app-icon.swift` 再重新生成，
不要直接编辑 `.appiconset` 里的 PNG（那些是产物）：

```sh
cd macos-native
swiftc -O -parse-as-library scripts/make-app-icon.swift -o /tmp/mkicon
/tmp/mkicon iconset WorkFollow/Resources/Assets.xcassets/AppIcon.appiconset
```

两个必需的编译开关：

- **`-parse-as-library`**：脚本用 `@main`，不加这个参数 swiftc 会报
  `'main' attribute cannot be used in a module that contains top-level code`。
- **渲染必须在 `@MainActor static func main()` 里**：`ImageRenderer` 是 `@MainActor` 隔离的，
  在顶层裸写会报 `call to main actor-isolated initializer 'init(content:)' in a synchronous
  nonisolated context`。

需要独立 `.icns` 时：

```sh
cp -R <上面的 appiconset 目录> /tmp/AppIcon.iconset
iconutil -c icns -o WorkFollow.icns /tmp/AppIcon.iconset
```

## 验证

| 检查 | 结果 |
| --- | --- |
| 构建 | `BUILD SUCCEEDED`（要加 `OTHER_SWIFT_FLAGS='$(inherited) -Xfrontend -disable-sandbox'`，见下） |
| actool 是否按 app icon 编 | 命令行里出现 `--app-icon AppIcon`，产出 `AppIcon.icns` + `Assets.car` |
| 产物是否进包 | `WorkFollow.app/Contents/Resources/` 下有 `AppIcon.icns`(46KB) 与 `Assets.car`(393KB) |
| Info.plist | `CFBundleIconName = AppIcon`，`CFBundleIconFile = AppIcon` |
| 系统实际取到什么图 | `NSWorkspace.icon(forFile: <app>)` 返回 16/32/64/128/256/512/1024/2048 各档，与生成器输出平均差 **3.25/255**；图里勾的实测中位色 `rgb(123,128,244)` = `#7B80F4` → 确认是新版而不是缓存 |
| 几何自检 | 512pt 下内容 bbox `41..470`，左右边距 41/41；「勾 + 间距 + 条」整组中心落在画布中心 (255.5, 255.5) |

`NSWorkspace.icon(forFile:)` 正是 Dock 与 Finder 取图标走的同一条 API，所以「系统认这个图标」
这一条是确定的。

### 没有做的验证（说清楚）

**没有把 app 跑起来截 Dock。** 原因是本机构建产物里 `WorkFollowAcceptanceStorageRoot` 是空的，
跑起来会直接写用户的真实数据目录；当时另一个会话的实例也在跑。两条加起来代价大于收益。
**所以「在 Dock 里的实际观感」是推断，不是实测**——判断依据是上面那条同源 API 的结果。
等方便时可以补一次真机 Dock 截图。

### 构建报 `SwiftUIMacros.StateMacro ... malformed response` 时

那是 **Swift 编译宏的子沙箱套不上**（agent 沙箱、CI 容器里常见），不是代码问题。
会连带报一堆假错误（`cannot find '_name' in scope` 之类）。加
`OTHER_SWIFT_FLAGS='$(inherited) -Xfrontend -disable-sandbox'` 绕开，本地 Xcode GUI 构建不需要。

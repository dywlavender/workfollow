# 打勾 macOS 个人版设计方案

状态：设计基线 v0.1
目标平台：macOS 15 及以上
产品形态：本地优先、单用户、无需登录的个人任务与笔记应用
技术前提：Flutter 桌面端；不使用 WebView，不启动本地 HTTP 服务

## 1. 结论

macOS 个人版不是现有 WorkFollow 网页端的缩小版，而是一款围绕“快速收集、安排今天、专注完成、随手沉淀”重新设计的桌面应用。

设计方向定义为 **Quiet Seasonal / 静谧四时**：

- 主体界面接近 macOS 原生生产力工具的克制与秩序感。
- 用低饱和强调色、轻材质和短促动效建立精致感。
- 四季场景只出现在侧栏、空状态和完成反馈等低信息区域，不覆盖正文和任务列表。
- 高级感来自比例、排版、层级和操作连续性，不依赖大面积粉色、强玻璃、发光或持续飘落动画。

首版只做个人能力：任务、清单、日历、笔记、提醒、搜索、备份和个性化。账号、团队、指派、审批、评论、审计、共享与实时协同均不进入 macOS 个人版。

## 2. 产品目标

### 2.1 核心体验

用户打开应用后，应能在十秒内完成以下任一行为：

1. 记录一件稍后处理的事。
2. 看清今天真正要做什么。
3. 修改任务的时间、清单或优先级。
4. 找到一条任务或笔记。
5. 勾掉一件事，并明确知道结果已经保存。

### 2.2 设计原则

1. **内容先于装饰**：任务标题、时间和状态始终比主题背景更醒目。
2. **直接操作优先**：能在列表内完成的操作不打开表单；能拖动完成的安排不要求多次点击。
3. **键鼠同等完整**：所有高频动作既能用鼠标，也能通过菜单和快捷键完成。
4. **连续而非跳转**：列表、详情和编辑状态之间保持空间关系，不用网页式整页切换。
5. **安静但不迟钝**：反馈短、准、可打断；避免为了“灵动”而让高频操作反复表演。
6. **本地可信**：自动保存、撤销、备份和恢复都必须可见、可理解。

## 3. 功能边界

### 3.1 首版范围

- 收集箱、今天、计划、全部任务、已完成。
- 自定义清单、标签、优先级、截止时间、提醒、重复规则。
- 月历与日程式任务浏览。
- 个人笔记、文件夹、基础富文本、任务与笔记关联。
- 全局搜索和命令面板。
- 菜单栏快速添加、可配置全局快捷键、系统通知。
- 本地数据库、附件目录、自动备份、导入和导出。
- 浅色、深色、跟随系统；经典主题与四季主题。

### 3.2 后续范围

- 专注计时和完成统计。
- 自然语言日期解析。
- 多窗口笔记编辑。
- Shortcuts、Spotlight 和 App Intents 集成。
- iCloud 或自建同步。

### 3.3 明确不做

- 登录、注册和用户头像。
- 团队、成员、任务指派和审批。
- 通知中心式消息流。
- 评论、共享、版本审核和审计日志。
- 实时协同和在线状态。

## 4. 信息架构

### 4.1 主导航

侧栏按工作心智而不是现有网页模块划分：

```text
智能清单
├── 收集箱
├── 今天
├── 计划
├── 全部任务
└── 已完成

内容
├── 日历
└── 笔记

我的清单
├── 工作
├── 学习
└── 用户自定义…
```

搜索不是固定页面，通过工具栏搜索框或 `Command-K` 唤起；设置不占用侧栏底部关键位置，通过应用菜单或 `Command-,` 打开独立设置窗口。

### 4.2 主窗口

默认窗口采用可调整的三栏结构：

```text
┌───────────────────────────────────────────────────────────────┐
│ macOS 标题栏 / 工具栏：侧栏 · 当前视图 · 搜索 · 新建       │
├──────────────┬────────────────────────┬───────────────────────┤
│ 侧栏         │ 任务或笔记列表         │ 详情检查器            │
│ 200–260 pt   │ 340–460 pt             │ ≥ 420 pt               │
│              │                        │                        │
│ 智能清单     │ 今天                   │ 任务标题               │
│ 内容         │ 快速添加               │ 日期 / 提醒 / 清单      │
│ 我的清单     │ 分组后的任务行         │ 描述 / 子任务 / 附件    │
└──────────────┴────────────────────────┴───────────────────────┘
```

- 推荐初始尺寸：1180 × 760 pt。
- 最小尺寸：880 × 600 pt。
- 侧栏可隐藏；窄窗口优先收起详情，再自动收起侧栏。
- 详情区是 trailing inspector，不做网页式抽屉，不覆盖任务列表。
- 关闭详情后，列表扩展为主内容区；双击任务可在独立窗口打开，列入后续版本。
- 分栏宽度和窗口位置在下次启动时恢复。

### 4.3 工具栏

工具栏融入 macOS 标题栏，仅放高频动作：

- 左侧：显示/隐藏侧栏、返回、当前视图标题。
- 中部：可收缩搜索框。
- 右侧：筛选、视图选项、新建任务。

所有工具栏命令在菜单栏中都有对应入口，避免用户隐藏工具栏后失去功能。

## 5. 核心页面

### 5.1 今天

今天是默认首页，不再单独制作信息重复的仪表盘。

页面由四部分组成：

1. 日期、星期、未完成数量和轻量问候。
2. 单行快速添加区。
3. 过期、今天、稍后三个任务组。
4. 可折叠的已完成任务。

任务行默认高度 44 pt，显示：完成按钮、标题、必要的时间信息以及最多两个辅助标记。描述、全部标签、附件和重复规则只在详情区呈现，避免列表成为徽章集合。

### 5.2 收集箱与清单

- 收集箱强调无摩擦记录，不要求先选择日期或清单。
- 自定义清单支持手动排序、分组和颜色标识。
- 拖到侧栏清单即完成移动；拖到“今天”即安排到今天。
- 多选后，详情区切换为批量编辑检查器。

### 5.3 计划

采用“日期时间轴 + 任务列表”，用于未来七天到一个月的安排。首版避免实现复杂甘特图。

- 顶部横向日期条支持键盘左右切换。
- 无日期任务可从暂存区拖入某天。
- 跨天任务使用连续但低对比度的时间条，不抢占标题。

### 5.4 日历

- 月视图是默认视图，周视图后续补充。
- 点击日期在右侧显示当日任务，不打开新的模态页。
- 拖动任务修改日期，拖到日期边缘时自动翻月。
- 月格只显示有限条目，剩余数量通过“另有 N 项”进入当日列表。

### 5.5 笔记

笔记继续使用三栏结构：文件夹、笔记列表、编辑器。进入笔记后，主侧栏切换为笔记文件夹上下文，工具栏保留返回任务区的入口。

首版富文本支持：

- 一级至三级标题、正文、加粗、斜体、删除线。
- 有序列表、无序列表、任务列表、引用、代码块。
- 链接、图片和附件。
- `[[` 关联现有笔记，`/任务` 将选中文本转为任务。

表格、复杂嵌入、协同光标和版本审批不进入首版。

### 5.6 搜索与命令面板

`Command-K` 打开居中的命令面板，统一搜索任务、笔记和命令：

- 输入内容后先显示匹配结果，再显示可执行命令。
- 支持自然语言范围词，例如“今天”“已完成”“工作清单”。
- 上下键选择，Return 打开，Command-Return 在新窗口打开预留给后续版本。
- 空输入时展示最近访问和常用命令，不显示营销式空状态。

### 5.7 设置窗口

设置使用独立 macOS 窗口，分为：通用、外观、提醒、数据、快捷键、关于。

数据页必须明确显示数据库和附件所在位置、最近备份时间、立即备份、恢复、导出和打开数据目录。

## 6. 视觉方向：Quiet Seasonal

### 6.1 主视觉

默认主题采用“墨紫 + 暖白 + 雾灰”：

- 强调色只用于选中、主要按钮、完成反馈和焦点。
- 正文表面保持近白或近黑，保证长时间阅读舒适。
- 侧栏使用系统材质感，但不叠加多层半透明卡片。
- 列表通过留白和微弱分隔组织，不把每个任务装进卡片。
- 阴影只用于悬浮层、命令面板和拖动元素；主布局用边界和材质区分。

现有春季主题的粉色和插画可以保留，但需要降级：

- 场景主要出现在侧栏底部或空白区域，整体不超过窗口视觉面积的 20%。
- 任务列表和编辑器永远使用稳定内容表面，不让粉色背景穿透正文。
- 花瓣默认静态；只有完成一组任务等低频时刻才出现一次短动画。
- 深色模式重新配色，不通过简单降低亮度得到。

### 6.2 字体

- 中文和界面文字优先使用系统字体：SF Pro / PingFang SC。
- 正文 13 pt，辅助信息 11–12 pt，列表标题 13–14 pt。
- 页面标题 20–22 pt，编辑器标题 24–28 pt。
- 数字时间使用 tabular figures，避免列表时间宽度跳动。
- 不额外引入展示字体；品牌感由图标、色彩和版式建立。

### 6.3 图标

- macOS 版本优先采用 SF Symbols 语义和尺寸规范。
- 主导航使用 16 pt 图标，工具栏使用 15–17 pt 图标。
- 图标默认单色，不给每个侧栏项目固定彩色图标。
- 自定义“打勾”标志只用于应用图标、欢迎和完成反馈，不替代通用功能图标。

### 6.4 形状与层级

- 小控件圆角：6 pt。
- 输入框、分段控件：8 pt。
- 浮层和命令面板：12–14 pt。
- 胶囊只用于标签、筛选条件和极少量状态，不用于所有按钮。
- 列表选择态使用柔和底色和 6 pt 圆角，不使用整行高饱和填充。

## 7. 设计令牌

Flutter 端使用三层令牌，不在组件内直接写颜色和尺寸。

```text
Primitive
├── neutral / plum / seasonal / status
├── spacing / radius / type / duration
↓
Semantic
├── canvas / sidebar / content / inspector / overlay
├── text-primary / secondary / tertiary
├── accent / success / warning / danger
↓
Component
├── task-row / sidebar-item / quick-add
├── inspector-field / command-panel / popover
└── checkbox / button / input / tag
```

建议基线值：

| 类别 | 基线 |
| --- | --- |
| 间距 | 4、8、12、16、20、24、32 pt |
| 控件高度 | 紧凑 28 pt、标准 32 pt、突出 36 pt |
| 任务行 | 标准 44 pt、舒适 52 pt |
| 圆角 | 4、6、8、12、14 pt |
| 快速反馈 | 90–120 ms |
| 状态切换 | 140–180 ms |
| 面板过渡 | 180–240 ms |
| 焦点环 | 2 pt，跟随系统强调色或应用强调色 |

浅色与深色模式只覆盖语义层；组件令牌保持同一角色关系。四季主题替换强调色、侧栏材质和装饰资源，不修改正文对比度规则。

## 8. 组件规范

### 8.1 任务完成控件

- 默认是 18 pt 空心圆，命中区不小于 28 × 28 pt。
- Hover 时边框增强并轻微填充，不缩放整个任务行。
- 点击后 120 ms 内完成描边到填充的变化，勾号随后出现。
- 任务标题在 160 ms 内降低对比度；列表重排延迟到反馈可感知后开始。
- 完成后提供 5 秒可撤销反馈，不弹确认框。

### 8.2 任务行

状态必须覆盖 default、hover、selected、focused、dragging、completed、disabled。

- Hover：仅出现尾部快捷动作和轻微背景变化。
- Selected：使用柔和强调色表面，同时保留清晰键盘焦点。
- Dragging：提高层级和阴影，原位置保留占位。
- Completed：降低标题对比度，但不能低到无法阅读；不只依赖删除线。

### 8.3 快速添加

- 默认是一行安静输入，不做大卡片。
- 输入后逐步显露日期、清单、提醒等结构化字段。
- Return 创建；Shift-Return 换行；Command-Return 创建并打开详情。
- 解析出的日期以可撤销 token 显示，不悄悄改变原文含义。

### 8.4 详情检查器

- 标题直接编辑；属性采用标签 + 值的两列结构。
- 日期、清单、提醒等使用 popover，不连续打开多层模态框。
- 描述和子任务占据主要阅读空间，属性区可折叠。
- 删除放入“更多”菜单，并提供可撤销机制；永久清空时才二次确认。

### 8.5 浮层

- 菜单、popover、命令面板和对话框使用不同层级，不能统一成大白卡片。
- 菜单用于短命令；popover 用于日期和属性编辑；对话框只用于阻断性决策。
- 浮层出现位置必须与触发控件有空间关系，关闭后焦点返回触发点。

## 9. 动效语言

动效的关键词是 **跟手、短促、连续、可打断**。

### 9.1 使用动效的场景

- 勾选、撤销、拖动和排序。
- 侧栏、详情检查器的展开与收起。
- 快速添加从一行扩展为结构化编辑。
- 搜索结果更新和命令面板出现。
- 低频完成里程碑的品牌反馈。

### 9.2 不使用动效的场景

- 每次切换侧栏条目时播放整页入场。
- 列表滚动时持续视差或背景粒子。
- 高频 Hover 引发缩放、弹跳或模糊变化。
- 保存时反复弹出成功动画。

### 9.3 减少动态效果

响应 macOS“减少动态效果”：

- 位移和缩放改为短淡入淡出。
- 取消背景粒子、弹簧回弹和大范围模糊过渡。
- 保留状态颜色、文字和图标反馈，不能让动效成为唯一信息来源。

## 10. macOS 操作契约

### 10.1 快捷键

| 快捷键 | 行为 |
| --- | --- |
| Command-N | 新建任务 |
| Command-Shift-N | 新建笔记 |
| Command-K | 搜索与命令面板 |
| Command-, | 设置 |
| Command-1 | 今天 |
| Command-2 | 收集箱 |
| Command-3 | 计划 |
| Command-4 | 日历 |
| Command-5 | 笔记 |
| Space | 完成或取消完成当前任务 |
| Return | 打开或编辑当前项 |
| Delete | 移到废纸篓 |
| Command-Z | 撤销最近操作 |

全局快速添加快捷键不预设强占系统组合键，首次启用时由用户选择并可随时修改。

### 10.2 菜单栏

应用菜单至少包含：文件、编辑、视图、任务、笔记、窗口、帮助。所有工具栏高频动作都在菜单中可发现，并显示对应快捷键。

### 10.3 右键与拖放

- 任务、笔记、清单、标签均提供上下文菜单。
- 从 Finder 拖入文件可附加到当前任务或笔记。
- 任务可在列表内排序，也可拖至侧栏清单或日期目标。
- 拖放失败必须恢复原位置并说明原因。

## 11. 空状态与反馈

- 空状态以一句结果说明和一个主动作结束，不使用大段宣传文案。
- “今天没有任务”可显示低密度季节插画，但不持续运动。
- 自动保存不持续提示；只有失败或退出前仍未落盘时才显式提醒。
- 成功反馈尽量在操作位置附近完成；错误信息说明发生了什么和下一步怎么办。
- 删除任务默认进入废纸篓，避免频繁确认；清空废纸篓需要明确确认。

## 12. 无障碍与质量底线

- macOS 普通控件推荐命中区 28 × 28 pt，不低于 20 × 20 pt。
- 正文文字对比度至少 4.5:1，非文字控件与焦点指示至少 3:1。
- 不用颜色单独表达优先级、错误或完成状态。
- 完整支持键盘焦点、VoiceOver 标签和系统文字缩放。
- 浅色、深色、高对比度、减少透明度、减少动态效果逐项验收。
- 任务数达到一万条时，滚动、搜索、拖动和启动性能仍需保持可用。

## 13. 第一轮原型

在开发完整应用前，只实现一个可交互的“今天”窗口，用它验证技术与审美：

1. macOS 标题栏和可折叠侧栏。
2. 今天任务列表、快速添加、分组和空状态。
3. 任务详情检查器。
4. 勾选、撤销、拖动排序和键盘导航。
5. 命令面板。
6. 浅色与深色模式。
7. 经典主题和一个降噪后的春季主题。

原型不连接完整业务数据库，可使用固定数据；通过后再冻结窗口结构、视觉令牌和动效参数，进入功能开发。

### 原型验收问题

- 缩放到 880 × 600 pt 时是否仍能完成核心任务？
- 连续创建、安排和完成十个任务时是否存在多余步骤？
- 只用键盘能否完整操作？
- 春季主题关闭后，产品是否仍有独立辨识度？
- 深色模式是否真正重新设计，而不是简单反色？
- 动效关闭后，信息和反馈是否仍完整？
- 使用十五分钟后，装饰是否开始干扰阅读？

## 14. 后续设计交付物

1. 1180 × 760 pt 的今天页浅色和深色高保真稿。
2. 880 × 600 pt 紧凑窗口适配稿。
3. 侧栏、任务行、快速添加、详情检查器和命令面板组件状态表。
4. 经典、春、夏、秋、冬五套语义颜色令牌。
5. 勾选、拖动、面板和搜索四组动效原型。
6. Flutter 组件与设计令牌命名对照表。
7. VoiceOver、键盘、减少动态效果验收清单。

## 15. 设计依据

- Apple 建议 macOS 应用充分利用可调整窗口、大屏信息密度、菜单栏、键盘快捷键和个性化能力：<https://developer.apple.com/design/human-interface-guidelines/designing-for-macos/>
- Apple 建议侧栏可隐藏、随窗口尺寸调整，并避免把关键动作放在侧栏底部：<https://developer.apple.com/design/human-interface-guidelines/sidebars>
- 工具栏只承载高频动作，而且每个工具栏命令都应在菜单栏中可用：<https://developer.apple.com/design/human-interface-guidelines/toolbars>
- 动效应简短、有目的、可取消，并响应“减少动态效果”：<https://developer.apple.com/design/human-interface-guidelines/motion>
- macOS 无障碍控件尺寸和减少动态效果要求：<https://developer.apple.com/design/human-interface-guidelines/accessibility>

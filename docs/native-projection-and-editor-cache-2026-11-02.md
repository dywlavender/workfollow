# 任务投影与编辑器缓存优化

日期：2026-11-02

## 已修改的路径

- 普通任务标题、正文更新后，保留不受影响的分组、任务树和侧栏计数缓存。再次读取时从 store 刷新任务值，避免旧标题、正文留在缓存里。
- 列表排序移到节点缓存内部；缓存命中时不再先排序一次。缓存区分排序方式和方向。
- 正文高度测量按文档身份、文本存储版本、宽度和排版参数缓存。SwiftUI 无关更新不再反复要求 TextKit 布局全文。
- 同一文本存储版本的重复编辑通知跳过解码；真正输入、文档命令和强制提交仍走原来的提交流程。

## 正确性边界

搜索和已保存筛选器仍重新判断成员；重命名使标题排序失效，正文或标题更新使修改时间排序失效。完成状态、日期、优先级、清单、父子关系等业务变更继续使用完整投影失效路径。正文编辑若同时推导出检查清单完成等业务变化，也走完整失效路径。

窗口宽度、字号、正文格式、文本存储和文档切换均参与高度缓存判断。回归包含真实 SwiftUI 宿主中的输入法组合文本：模型尚未提交时，编辑器仍随内容增高。

撤销历史没有改写。现有快照使用 Swift 值类型的写时复制，文本提交不新增业务撤销帧；本次没有得到“每次编辑深拷贝整个工作空间”的证据。

## 对照结果

500 条虚构任务，预热收集箱、今天、所有任务的分组和节点，以及今天侧栏计数。随后进行 20 轮编辑，每轮修改父任务正文和子任务标题，再读取三个范围及计数，共 40 次文本修改。

| 指标 | 优化前 | 优化后 |
| --- | ---: | ---: |
| 上述过程中的投影重建次数 | 140 | 0 |
| 同内容、同宽度的 31 次尺寸请求所需的实际测量次数 | 原路径每次测量 | 1 |

每轮检查最新标题和正文、侧栏计数及子任务进度。缓存仍需刷新可见任务值，这个结果不表示没有计算，也不等于界面延迟归零。

## 验证

- 当前主目录累计完成 149 个不同相关用例，涵盖投影、排序、搜索、业务撤销、文本更新、视图复用、笔记切换、输入法、正文滚动、悬浮编辑器和字号。
- 整组运行时 146 个通过，另外 3 个正文滚动用例遇到 Mac 锁屏、鼠标事件未生效。原生窗口工具确认解锁后，在不改代码的情况下补跑完整 `EditorBodyScrollTests`，4 项全部通过，包含这 3 个用例。149 个用例均已有通过结果，未将锁屏时的失败当作通过。
- 编辑器缓存类的 5 个用例通过，包含真实 SwiftUI 宿主在模型尚未提交时随输入法组合文本增高的检查。
- Release 构建及本机签名验证通过。
- 本轮未替换日用 App，未将构建结果当作用户实际交互验收。

同时修正两处现有测试夹具：颜色浮条按现有的主题包装宿主检查复用，并通过原生格式命令验证选区颜色；选择刷新测试改为载入已有任务，避免新建高亮两秒后自动消失的事件混入统计，保留原有全部刷新断言。

## 尚存的开销

真实正文编辑仍同步执行完整 `DocumentTextCodec.decode`，本次仅省去相同文本存储版本的重复通知。缓存刷新也仍遍历缓存中的任务；没有实现逐段解码或逐行差量发布。本轮测量的是重建和布局次数，没有测得新的实机页面切换毫秒数。

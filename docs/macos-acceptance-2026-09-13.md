## 仍需修复的问题

### A1 · P1：“转换为纯文本副本”实际覆盖原笔记

**证据：源码与行为探针。**

- 操作：导入一条带链接的笔记，执行界面名为“转换为纯文本副本”的操作。
- 结果：笔记数量仍为 1，原 ID 被原位改写，同时清空 `originalContentJson`；并没有留下富文本原件和新的纯文本副本。
- 原因：`convertNoteToPlainText` 调用 `_replaceNote`，并设置 `clearOriginalContentJson: true`。
- 影响：界面承诺会得到副本，实际移除了当前笔记中保留的原结构。“可以从 Web 重新导出”的提示不能代替本机保留原件。
- 位置：[覆盖与清空原件](/Users/dongyangwei/Documents/学习/代办笔记/workfollow-flutter-personal/desktop/lib/state/workspace_controller.dart:1851)、[确认弹窗文案](/Users/dongyangwei/Documents/学习/代办笔记/workfollow-flutter-personal/desktop/lib/screens/notes_screen.dart:567)。
- 修复建议：创建新 ID 的纯文本笔记并切换到副本，原笔记及其结构保留。验收应确认两条记录均存在、原件链接仍在、副本可独立编辑。

### A2 · P2：逐字追加新行时，结构化正文停在第一个字符

**证据：模拟 TextField 每次 `onChanged` 的行为探针。**

- 操作：导入正文为“资料”的链接笔记，依次输入 `资料\n`、`资料\na`、`资料\nab`。
- 结果：`plainText` 是完整的 `资料\nab`，但 `contentJson` 的文字投影只有 `资料\na`。原链接仍保留，当前界面文字没有丢失；不一致发生在持久化的两份正文之间。
- 原因：`appendToRichContent` 每次用已追加过的 `contentJson` 重新计算基线。输入 `a` 后，基线变成 `资料\na`；下一次 `ab` 不满足“基线＋换行”，被当作修改受保护内容而放弃更新结构化正文。
- 影响：按正常打字方式补充内容，结构化正文就落后于用户看到的正文。现有测试一次传入整段“新增段落”，因此没有覆盖这个过程。
- 位置：[变动的追加基线](/Users/dongyangwei/Documents/学习/代办笔记/workfollow-flutter-personal/desktop/lib/models/task.dart:501)、[不同步时仍保存 plainText](/Users/dongyangwei/Documents/学习/代办笔记/workfollow-flutter-personal/desktop/lib/state/workspace_controller.dart:1824)。
- 修复建议：使用固定的导入原文作为基线，更新完整的新增部分，或将新增内容独立建模；允许继续编辑自己刚追加的那一行。验收使用逐字输入与退格，确认最终两份正文一致且原链接保留。

### A3 · P2：首页月历只能显示部分日期

**证据：正式版截图、布局源码与 Widget 探针。**

- 操作：以当前正常窗口宽度打开首页。今天卡片已占满内容宽度，但日历卡片只显示开头的日期，后面各周被裁掉。
- 原因：卡片固定为 250 pt 高；内部 `GridView` 使用默认正方形格子，宽度越大，格子越高，同时禁用滚动。调整卡片宽度没有同时调整月历行高。
- 探针：在 1068 pt 内容区域宽度（1280 pt 窗口扣除 212 pt 侧栏）下，禁用滚动的月历仍有约 551.86 pt 内容超出视口。
- 位置：[月历网格](/Users/dongyangwei/Documents/学习/代办笔记/workfollow-flutter-personal/desktop/lib/screens/home_screen.dart:459)。
- 修复建议：按可用高度与当月周数计算行高，明确设置 `mainAxisExtent` 或等效布局。验收检查单列和双列时整月日期都可见。

# 任务行差量刷新与性能验证

日期：2026-10-07；分支：`experiment/macos-native`。

## 实现

任务列表将结构、内容、尺寸变化分开处理。行 ID 顺序变化仍更新列表结构；顺序不变时，只更新展示数据发生变化的可见单元格，只对尺寸条件变化的行通知重新测量高度。未显示行也更新数据与高度失效状态，显示时按最新数据创建内容。

行内容通过闭包按需创建，不再提前为整批行创建 AnyView。没有变化的行保持原 HostingView 内容。展示比较包括任务、层级、展开、选中与批量选择、元信息偏好、拖拽状态、子任务进度、日期和日期修订。尺寸比较包含正文预览显隐、完成状态和层级，继续使用原有自动行高和布局约束。

任务行、元信息、拖拽修饰器不再直接订阅整个 TaskWorkspaceModel。列表负责提供变更后的行数据，行内操作仍调用原模型，浮层保留自身需要的观察。编辑中的标题仍使用原有编辑会话保护，不覆盖未提交草稿。

子任务进度按任务 revision 缓存：任务变更后一次遍历生成所有父任务的进度，选择与列宽变化不重新扫描。正文预览按块提取第一条非空行，找到后停止，不再先拼接完整正文。非“今天”列表也不再计算倒数纪念日投影。

## 测量

使用本机 arm64 Debug 构建、实际 43 条任务、1280×800 测试窗口，沿用导航和布局探针：赋值目的地、布局、运行主循环至少 5ms、再次布局。以下为 CPU 侧探针，不能视为鼠标点击到屏幕完整帧的延迟。

本轮修改前重新测量的重复进入样本，与最终构建的两次重复进入样本：

| 操作 | 本轮修改前 | 最终构建 |
| --- | ---: | ---: |
| 再次进入收集箱 | 138–145ms | 88–89ms |
| 再次进入今天 | 155–166ms | 108ms |

任务选择全壳探针（30 次切换）中位数约 47ms，95 百分位约 53ms；此前页面缓存版本的中位数约 82ms。不同操作的探针不能混为一个指标。

首次进入收集箱仍需约 333ms，首次创建问题没有被这轮优化消除。

简单行的关闭内容刷新/关闭高度失效对照，10 次更新分别约 60ms、62ms、60ms、58ms，且每次包含至少 5ms 主循环等待，差异很小。因此没有足够证据把整页收益归因于单一操作。上述收益来自差量刷新、缩小观察范围等组合修改。

无变化行探针中，原实现 10 次更新设置可见行内容 130 次、使行高失效 130 次；新实现均为 0。独立回归验证选择变化只更新对应行，不使行高失效。

## 验证

65 项不同的相关测试分批通过。覆盖任务选择、标题编辑草稿与焦点、拖拽、行几何、日历投影、返回页面、隐藏期间任务变更、未显示行的高度变化、无变化行跳过构建、折叠父任务的子任务进度与撤销。

父任务测试检查模型进度与同一个原生单元格的实际重新配置；本机 XCTest 窗口的 SwiftUI 虚拟文字未能通过通用无障碍读取获得，所以不将该读取结果用作文字显示断言。

最新应用已启动。实际验证收集箱滚动、离开到笔记、再次进入收集箱，滚动位置保留，任务标题、预览、元信息和分组布局正常。

## 后续空间

当前仍有整页布局与主循环成本。列表结构变化还使用 reloadData；每个任务范围仍保留自己的页面与行宿主。这轮保留了现有页面状态和编辑行为，共享容器、增量插入删除，以及进一步拆分列表与详情的观察范围，需在独立测量后决定。
